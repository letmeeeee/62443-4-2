# Modbus TLS 桌面客户端与服务端

Windows 一键打包与 EXE 使用步骤见 [WINDOWS.md](WINDOWS.md)。构建机双击 `build_windows.bat`，生成 `dist/ModbusTLS.exe`；目标电脑无需安装 Python 或 OpenSSL。在 Linux 开发机运行 `python3 -m tools.modbus_gui.prepare_windows` 可生成不包含用户证书与私钥的构建源码包。

独立工具，使用 Python 标准库 Tkinter 和 ssl，不依赖 Flask、设备数据库或 OP-TEE。支持 TLS 1.2 及以上、双向证书认证、公开证书导入/导出、证书信息查看和一键生成联调证书。

## 启动

在仓库根目录运行：

```bash
# 客户端窗口
python3 -m tools.modbus_gui --role client

# 服务端窗口（也可在同一窗口内切换两个页签）
python3 -m tools.modbus_gui --role server
```

源码运行需要 Python 3.8+ 与桌面环境。Ubuntu 如缺少 Tkinter，安装 `sudo apt install python3-tk`；查看和生成证书使用 OpenSSL 1.1.1+，通过 `openssl version` 检查，Linux 企业CA功能需安装本目录 requirements.txt。新的企业 CA CSR/导入流程在所有平台均需 cryptography>=42；Windows 推荐 Python 3.12 x64 并启用 Tcl/Tk，源码运行时需安装 cryptography；EXE 打包脚本会自动安装并内置所需依赖，目标电脑无需安装 Python 或 OpenSSL。

## 本机快速联调

1. 打开「证书管理 / 快速联调」，SAN 保持 `127.0.0.1`，点击「生成联调证书并配置两端」，选择保存目录。程序在其中新建唯一子目录，不覆盖旧证书。
2. 打开「服务端」，保持监听 `127.0.0.1:18020`、站号 1，点击「启动服务端」。
3. 在服务端寄存器操作中填写起始地址 `0`、写入值 `123, 456`，点击「设置本地寄存器值」。
4. 打开「客户端」，选择 `03 保持寄存器`、地址 `0`、数量 `2`，点击「发送请求」，结果为 `123, 456`。
5. 选择功能 `06` 或 `16` 可写入服务端保持寄存器。写入数量由「写入值」个数决定；06 只能提供一个值。服务端点击「刷新寄存器」可查看结果。

两个窗口分别运行时，生成证书的窗口会自动配置两端；另一个窗口须手动导入同一生成目录内对应的身份证书、私钥及对端公开证书。

## 连接当前 CA-only EMS 设备

源码环境先安装 `python3 -m pip install -r tools/modbus_gui/requirements.txt`（cryptography>=42）。Linux 发行包已带依赖。当前设备不再支持 trust-add 或设备直接自签身份。

1. 在「证书管理 / 快速联调」的「企业 CA 身份」填写 PC 身份编号（例如 PC-debug-001）。选择 master 表示 GUI 客户端，slave 表示 GUI 模拟服务端；slave 的 SAN 填写设备实际连接的 PC IP。
2. 点击「生成私钥并导出 CSR 请求包」，选择保存父目录。程序新建独立身份目录，内有 `master.key` 或 `slave.key` 和 `request/`。**只把 request 子目录交给 CA，私钥留在 PC。**
3. 新版 CA 管理工具中，「CSR 交接目录」选上述 request 目录，预览角色/CN/IP，批准并「签发证书包」。原三身份设备交接包继续支持，不需为 PC 伪造三份 CSR。
4. 返回调试工具，选择原本地身份目录，点击「导入 CA 签发包并配置角色」，选择 CA 输出目录。可提前填写可信根 SHA-256；留空时读取包内根指纹，独立核对可信 CA 来源后确认。
5. 程序检查单角色清单/摘要、设备编号、角色、CSR/公钥/SAN、本地私钥匹配、链签名/有效期及根指纹，复制公开 fullchain/roots 到本地版本目录，自动配置对应页签。重复导入同一证书会拒绝，直接使用已有路径即可。
6. 客户端保持「发送客户端证书」「验证服务端证书」勾选；目标填设备 IP 和实际 TLS 端口。模拟从机保持「验证客户端证书」勾选，监听可填0.0.0.0，证书 SAN 仍需真实 PC IP。修改服务端身份后停止并重新启动监听。

客户端使用本次企业 CA 的 clientAuth 身份；服务端使用同体系 serverAuth 身份。GUI 客户端默认验证实际连接IP/名称；设备 tems 主机要求 GUI 服务端证书包含实际连接 PC IP SAN。无需向设备导入 PC 私钥或逐个叶证书；设备已有企业根时可验证对应链。CA 受信不等于寄存器写权限已获业务授权。

单角色请求包 kind=`lc400-role-csr`，含 manifest.json 和角色.csr；返回包 kind=`lc400-role-certificates`，含角色-leaf.pem、roots.pem、intermediates.pem、manifest.json、deployment.json。私钥不会进入交接包。签发纳入同一 CA 台账和吊销记录，不能用于PC SSH工具的三身份设备整包导入。

私钥当前未加密，以目录0700/文件0600保护；不可用普通共享目录保存。不自动替换已有密钥，续用同一 request 可续签。设备运行时未接入CRL/OCSP，CA记录吊销后仍需另行处理设备信任和身份。

## 隔离环境快速联调

原快速联调功能保留为隔离实验：默认使用临时测试 CA；旧自签叶证书选项明确标注不兼容当前设备。它们不应替代上述企业 CA 流程。CA根自身自签是正常PKI结构，与直接自签设备叶证书不同。

## 证书与跨机器连接

| 文件 | 用途 |
| --- | --- |
| `ca.crt` | 仅取消设备模式后生成，两端导入「可信 CA」 |
| `server.crt`、`server.key` | 服务端身份证书与私钥 |
| `client.crt`、`client.key` | 客户端身份证书与私钥 |
| `ca.key` | 仅取消设备模式后生成，CA 签发私钥不分发给对端 |

「导入」选择本地文件并引用其路径，不复制到系统证书库，不修改设备已有证书。支持 PEM 身份证书、PEM 私钥（可带密码）及 PEM CA 证书链。证书与私钥在连接/启动时校验；DER、PFX/P12 需要先转为 PEM。「导出」仅输出公开证书或 CA 证书链，拒绝包含私钥的文件；私钥需要由使用者安全转移至对应机器。

跨机器使用时，生成证书的 SAN 填写服务端实际 IP / DNS，服务端监听地址改为其网卡 IPv4 或 `0.0.0.0`，客户端目标填写服务端实际地址。`0.0.0.0` 仅用于监听。防火墙应允许所选 TCP 端口。若通过其他地址转发连接，可在客户端「验证服务端名称」中填写证书 SAN 内的 IP / DNS；留空则验证连接目标。

默认启用双向认证：客户端勾选「发送客户端证书」和「验证服务端证书」，服务端勾选「验证客户端证书」。这些选项可独立设置：

- 客户端取消「验证服务端证书」：跳过服务端证书链、有效期及 IP/DNS 名称校验，不读取信任栏文件，仍使用 TLS 加密。可以继续发送客户端证书，但此模式不满足当前设备双向身份验证的调试验收要求。日志显示「未验证服务端证书及名称」。此模式不确认服务端身份。
- 服务端取消「验证客户端证书」：不要求客户端证书，无需配置信任栏。修改后停止并重启监听生效。
- 客户端取消「发送客户端证书」：不加载客户端证书及私钥。对端要求客户端证书时仍会拒绝连接。

单次客户端请求读取当前 TLS 设置；循环模式使用启动时的设置，修改后须停止再启动循环。服务端须停止后重新启动。

生成证书有效期为 365 天，包含未加密的 RSA 私钥，仅供联调；生成目录在支持权限控制的系统上设为 0700、私钥为 0600。也可导入已有证书。当前设备调试应只导入可信企业 CA 根，证书栏加载叶证书及中间链。

## 协议范围与运行行为

客户端「寄存器操作」下方提供「循环间隔（毫秒）」「开始循环」「停止循环」和计数显示。默认间隔 1000 毫秒，可设置 10～3600000 毫秒。开始时保存当前连接、证书及寄存器参数，立即发送一次；每次请求完成或失败后等待所设间隔，再发送下一次。同一时刻只有一个请求，循环期间禁用单次发送与重复启动；修改参数需停止后重新开始。读取和写入功能均可循环，写入会重复发送启动时指定的值。

循环期间复用同一条 TCP/TLS 长连接，事务号逐次递增。失败记录到日志和失败计数，不连续弹窗；丢弃失效连接，在下一轮建立新连接。不会在同一轮自动重发请求；循环写入本身仍会在下一轮发送相同配置值，响应丢失时无法判断上一次写入是否已执行。「停止循环」取消后续发送；已经发出的请求等待完成或所设超时后结束，等待期间不能再次启动发送。停止后发送 TLS close_notify，等待对端关闭确认最多1秒；未收到确认只记录关闭提示，不把已完成请求改判失败。关闭窗口也停止后续循环，并等待在途请求与连接清理结束。每条 TX/RX 报文均包含 `YYYY-MM-DD HH:MM:SS.mmm` 时间戳，使用运行电脑的本地时间，在收发回调时记录，而非在 GUI 刷新时记录。

- 功能码：03 读保持寄存器、04 读输入寄存器、06 写单个保持寄存器、16（十进制，0x10）写多个保持寄存器。参考 [Modbus 官方协议规范](https://modbus.org/docs/Modbus_Application_Protocol_V1_1b3.pdf)。
- 地址使用协议零起始地址 0～65535，40001 编号对应地址 0。值为无符号 16 位整数，支持十进制和 `0x` 前缀；读取最多 125 个，批量写入最多 123 个。
- 服务端保持寄存器与输入寄存器各有 65536 个，初值全为 0，界面可分别修改。仅配置的 Unit ID 会被响应。数据在程序内存中保存，停止再启动监听会保留，退出程序后丢失。
- 单次发送使用独立 TLS 连接，完整响应后正常关闭；循环发送复用长连接，停止时关闭，异常后的下一轮重连；超时可设为大于 0 且不超过 120 秒。服务端支持最多 32 个并发连接，每个连接握手/收包超时 5 秒。
- GUI 日志显示毫秒时间、收发方向、客户端/服务端与对端地址、完整 ADU 十六进制（MBAP + PDU）、事务号、协议号、长度、站号、功能码，以及请求地址/数量、响应寄存器值或异常码。收发报文均取自实际发送/接收的应用层字节；显示的是 TLS 加密前/解密后的 Modbus 数据，不包含 TCP/IP 头或 TLS 密文记录。最大长度报文也完整显示，长行自动换行。保留最近约 1500 行日志。工具不访问或控制本仓库的实际设备服务。
- 此工具始终使用 TLS，不提供明文 TCP、串口 RTU 或完整 Modbus Security 角色授权功能。连接现有 EMS 时，需满足其客户端身份信任策略；客户端默认校验服务端身份，也可按上述选项关闭校验。

## 验证

完整 TX/RX 报文位于窗口下方的独立日志区：TX 蓝色表示本端发送，RX 绿色表示本端接收，每条均包含完整 ADU 十六进制。上下区域之间的分隔条可拖动调整高度，日志区保留最小高度；上方配置内容可使用右侧滚动条查看。日志只读，支持鼠标选择后 Ctrl+C、Ctrl+A 全选（macOS 使用 Command），右键菜单可复制所选、全选或复制全部；工具栏「复制全部」可直接复制当前全部日志。「清空日志」清除当前显示。

在仓库根目录运行，测试仅使用本机回环地址的临时端口与临时证书目录：

```bash
python3 -m unittest tools.modbus_gui.test_modbus -v
# 另有隐藏窗口 GUI 集成测试，需要有效的桌面 DISPLAY
python3 -m unittest tools.modbus_gui.test_gui -v
```

覆盖真实 TLS 读写、并发、错误 CA/名称/客户端身份拒绝、单向认证、证书导出再导入、报文边界及停止后重用端口。GUI 测试通过界面回调完成证书生成、服务端启动、客户端读写与停止/重启。

## 角色界面状态（2026-11-06）

企业CA页面切换master/slave时，身份编号、私钥身份目录、根指纹和SAN在当前窗口内分别保存并恢复，首次切到另一角色不沿用旧目录。master不需服务端SAN，该栏禁用；slave需填写运行模拟器的PC实际IP，而不是EMS设备IP。选择已有身份目录时读取request清单和CSR，恢复对应角色/编号/SAN；跨角色目录需确认切换。手工填写错角色目录会在导入前拒绝。生成或导入期间禁止重复操作，切换角色不会把后台生成结果写入另一角色。上述状态只在本次窗口内保留，尚不跨重启保存。
