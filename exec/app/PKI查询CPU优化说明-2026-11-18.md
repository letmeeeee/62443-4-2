# PKI 查询 CPU 优化说明

日期：2026-11-18。现有请求路径、参数和响应结构保持不变。

## 原因

安全中心的证书清单、状态和配置汇总会重复校验证书链、根、吊销状态并执行持钥自检。
公开密钥查询也会再次采集清单。一次清单采集包含多个 OpenSSL 子进程和 RSA 运算，
页面同时请求或频繁刷新时会重复计算，引起 CPU 峰值。

## 本次处理

- 新增 `utils/pki_read_cache.py`，仅缓存公开查询结果，最长 2 秒；不缓存私钥内容。
- 同一 Flask 应用进程共享清单缓存，合并并发重复查询；不同设备应用不共享结果。
- 证书清单和持钥自检结果分层复用，证书清单/状态/配置汇总可共享既有检查。
- CA 指纹、CRL 清单、HTTPS 状态和 Modbus 公开身份查询同样复用短缓存。
- 每次查询检查配置、根、CRL、三角色证书/私钥、身份来源、待应用标记、自检工具和
  目录的文件元数据版本，含 inode、大小、修改/变更时间、权限及所属用户；
  对受大小限制的 PKI 文件补充内容摘要，覆盖同大小写入且文件系统时间戳未变化的情况。
  私钥字节只用于流式摘要后丢弃，不保存在缓存中，摘要也不返回给前端。
  检测到变化立即重新采集，不必等待 TTL。系统时钟明显校正时也不复用旧结果。
- 收集期间版本发生变化时不保存缓存；异常不缓存，避免短暂故障长期固定。
- 返回深拷贝，调用方添加字段不会污染其他接口的数据。
- 导入、CSR 生成、custom/apply、显式 check/verify、导出和实际 TLS 校验不使用缓存。
  原有权限和 CSRF 校验仍在每个请求中执行。

缓存仅在进程内生效，多 worker 各自维护。首次查询、文件更新后和缓存到期后仍需
执行完整检查，不能承诺彻底消除 RSA 运算的 CPU 峰值。TEE 不可通过文件观察到的
外部状态变化，最多在该短缓存窗口后重新检测。状态中时间相关的信息也最多延迟
该窗口；实际 TLS/操作校验不受这个查询窗口影响。

## 本机样例

用真实 OpenSSL、临时 CA、master/HTTPS 身份做清单查询，并统计 OpenSSL 调用：

| 查询 | OpenSSL 子进程 | 本机耗时 |
| --- | --- | --- |
| 首次完整采集 | 45 | 约 242.2 ms |
| 紧接着重复读取 | 0 | 约 0.5 ms |

该数字只代表测试机样例，不是 EM-1000 上的 CPU 占用率测量。设备部署后应结合
页面轮询频率和实际进程 CPU 观察。自检诊断日志仅在实际重新检查时产生，缓存命中
不重复打印每个角色的检查日志。

## 部署与验证

同步 route_cert.py、route_security.py 和新增的 utils/pki_read_cache.py，并重启主
Flask 服务以加载代码。本次不需要重新编译 tems、自检程序，也无需替换证书或私钥。
这是 Flask 查询优化，不需要更新独立 HTTPS 维护脚本副本。

回归覆盖重复查询、并发合并、配置/根/私钥/权限/待应用标记变更、TTL 到期、时钟校正、
异常恢复、应用隔离、缓存期间文件变化，以及显式检查始终执行。
现有通用入口已允许 general/trina；相应旧测试改为使用 custom 作为非法值，不改变
本次优化前已经存在的模式校验行为。

验证结果：相关回归 174 项通过，8 项网络握手测试本轮未执行。性能探针另行执行通过。
