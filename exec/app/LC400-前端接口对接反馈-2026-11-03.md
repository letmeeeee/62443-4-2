# LC400 前端接口对接反馈与功能分工

更新日期：2026-11-04。接口入参与返回格式见第 10 章。对应需求清单第四、第五章的应用层接口。本反馈按本轮代码和隔离测试整理，目标设备部署、真实 MySQL 与浏览器联调仍需完成。

本轮已新增口令策略、失败锁定、服务端锁屏/解锁、账号启停与 UID、账号级会话撤销、结构化审计及导出、Banner、安全状态/配置摘要、证书清单、密钥引用、资源与组件清单、维护模式，以及保守范围的备份恢复、出厂基线恢复和应用身份清除接口。设备未提供的能力使用明确的不可用状态，不返回假正常。

## 1. 前端先统一认证和错误处理

### 1.1 请求与登录态

- 使用 `Authorization: Bearer <session_token>`，写请求同时携带 `X-CSRF-Token: <csrf_token>`；当前不使用登录 Cookie。
- Token、CSRF、身份信息放当前标签页 sessionStorage 或内存。移除 `token || "ok"`、环境变量占位 Token，缺少真实 session_token 时登录失败。
- 刷新时调用 `GET /permission/session`，更新用户名、UID、角色、锁屏与改密要求；不要只相信本地角色。
- 建议全部请求发送 `X-Tab-Id`：0–64 个字母、数字、下划线或连字符。后端记录到会话活动与审计；它不是身份凭据，多个标签使用同一 Token 仍属于同一会话。
- Socket.IO 握手使用 `auth: { session_token }`；切换账号时取消旧请求、断开旧连接后重连；退出时主动断开。
- 下载用带认证头的请求获取 Blob；不要把 Token 放 URL。上传用 FormData，由浏览器设置 multipart boundary。
- 使用同源 HTTPS 入口；本地开发通过同源代理，未开放任意跨域前端。

### 1.2 会话与错误码

默认绝对有效期 1800 秒、空闲有效期 900 秒，以部署配置和响应为准。**空闲以服务端收到的认证请求为活动依据**，后台轮询也会刷新；前端用户无操作锁屏需主动调用 `/permission/lock`，不能仅显示遮罩。

统一失败响应为 `{ ok:false, code, trace_id, message }`，响应头包含 `X-Trace-Id`。本地化提示按 code 映射，message 不作为业务判断条件。

| 状态 / code | 前端行为 |
|---|---|
| 登录 401 / INVALID_CREDENTIALS | 提示凭据错误，读取 attempts_remaining；不套用业务会话过期流程 |
| 429 / AUTH_LOCKED | 显示 lock_seconds 倒计时，不能用本地计数推断服务端已解锁 |
| 429 / LOGIN_LIMIT_REACHED | 会话数量已满，区别于口令锁定 |
| 429 / RATE_LIMITED | 请求过于频繁，降低轮询/重试频率 |
| 业务 401 / SESSION_INVALID | 清理该请求对应的本页会话并登录；避免旧请求清除刚创建的新会话 |
| 403 / SESSION_LOCKED | 显示锁屏，调用 verify 验密解锁，不清理有效 Token |
| 403 / PASSWORD_CHANGE_REQUIRED | 进入本人改密流程，完成后重新登录 |
| 403 / FORBIDDEN | 显示无权限，不统一跳登录 |
| 409 / MAINTENANCE_IN_PROGRESS | 维护期间业务写入被阻止，展示维护提示 |
| 5xx | 显示暂不可用及 trace_id，允许用户重试；不显示假成功 |

成功结构仍保留接口各自契约：权限/新增安全接口多数为 `ok:true`；审计查询直接返回分页字段；CA 证书与 TEE 接口为 `status:3`。前端不能给所有接口套同一个成功字段判断。

## 2. 登录、账号与会话页面

| 功能 | 接口 | 请求与响应 |
|---|---|---|
| 登录 | POST `/permission/login` | JSON：username,password；返回 session_token、csrf_token、expires_at（Unix 秒）、idle_timeout_minutes、uid、username、permission、first_login、password_expired、password_warning、password_expire_at、password_days_left、maintenance_until |
| 刷新恢复身份 | GET `/permission/session` | 返回 username、uid、permission、csrf_token、locked、password_change_required、idle_timeout_minutes、maintenance_until |
| 本页退出 | POST `/permission/logout` | `{}`；撤销当前会话 |
| 管理员按账号全部下线 | POST `/permission/logout` | `{"force":true,"username":"目标账号"}`；角色 4，返回 sessions_revoked |
| 会话列表 | GET `/permission/sessions` | 角色 4；sessions[] 含 session_id、username、expires_at、last_activity、tab_id、expired、current |
| 下线指定会话 | POST `/permission/sessions/revoke` | 角色 4；`{"session_id":"列表取得的标识"}` |
| 服务端锁屏 | POST `/permission/lock` | `{}`；锁屏后业务请求返回 SESSION_LOCKED |
| 验密解锁 | POST `/permission/verify` | `{"password":"当前口令"}`；成功 ok:true，失败不解除服务端锁定 |
| 用户列表 | POST `/permission/all` | 角色 4；`{}`，返回 ok、count、data[]；已移除密码哈希和 salt |
| 新增用户 | POST `/permission/add` | 角色 4；username、permission（整数 1–4）、password；必须提供符合策略的初始口令，首次登录要求改密 |
| 修改账号 | POST `/permission/update` | 角色 4；username 为目标账号，可提交 permission、enabled（布尔）或 status（enabled/disabled），以及 password |
| 本人改密 | POST `/permission/update` | username、old_password、password；普通用户只能修改本人密码，不可修改角色/启停/他人信息 |
| 删除账号 | POST `/permission/delete` | 角色 4；username；不允许删除自己，保留 UID 注销记录且禁止重用已删除用户名 |
| 重置口令 | POST `/permission/reset-password` | 角色 4；username、confirm:"RESET_PASSWORD"；返回 delivery_id、delivery、expires_in，不返回临时口令 |
| 口令策略 | GET `/api/security/password-policy` | 登录后读取，按返回策略设置表单规则 |
| 角色能力矩阵 | GET `/api/security/roles` | 角色 4；返回 abilities：能力名 → 允许的角色等级数组 |

用户列表新增 `uid,enabled,status,last_login`，保留口令生命周期展示字段。last_login 为 Unix 秒，空值表示尚无记录。用户名现设为不可变标识，前端改为只读；提交改名返回 USERNAME_IMMUTABLE。不能仅通过修改 first_login 绕过改密要求。

当前口令策略：12–128 字符，包含大写、小写、数字、非空白特殊字符，不包含用户名，不重复最近 5 次口令。连续失败阈值 5 次，锁定 300 秒，同时计账号与来源。旧加盐 MD5 在成功验证后迁移为 PBKDF2-HMAC-SHA256；新设口令使用 600000 次迭代。

改密、角色或启停变更会撤销该账号全部会话。本人改密成功后进入重新登录；管理员修改自己也可能使当前 Token 失效。开发账号仍受后端配置禁用，不能通过页面启用；不能删除或停用最后一个有效管理员。

重置口令由设备管理员在本地受限目录领取，接口不下发明文。前端展示领取编号及“联系设备管理员领取临时口令”，不要设计“API 返回密码弹窗”。临时口令有效期 24 小时，首次登录后只能进入改密流程。重置前二次确认。

登录和 session 响应中的 `loginSessions` 表示未过期且未空闲失效的登录会话数量；`webConnections` 表示主服务进程内 Socket.IO 连接数。二者上限当前均为 20，但不能当作用户数或标签页数。

| 功能 | 接口 | 请求与响应 |
|---|---|---|
| 登录前读取 Banner | GET `/permission/login-notice` | 无需登录；返回 enabled、text、version |
| 管理员更新 Banner | POST `/permission/login-notice` | 角色 4；`{"enabled":true,"text":"授权使用提示"}`；服务端递增 version |

Banner 用普通文本渲染。前端维护标识和倒计时使用 maintenance_until 或 until；不要自行假设启用状态。当前入口是后端管理员鉴权操作，尚无物理开关信号接入。维护期间大部分业务写操作会被拒绝，备份恢复、维护控制、退出/解锁等必要操作仍可用。

## 4. 审计查询、导出与容量

查询：`GET /api/history/getOperationlog`，角色 3/4。

```text
/api/history/getOperationlog?beginDt=2026-11-01T00:00:00&endDt=2026-11-03T23:59:59&pageNum=1&pageSize=20
```

| 参数 | 约定 |
|---|---|
| beginDt/endDt | 必填，设备本地时间 YYYY-MM-DDTHH:mm:ss，支持跨日；不传 Z 或时区偏移，开始不晚于结束 |
| pageNum/pageSize | 正整数，pageSize 为 1–500 |
| operator | 可选操作用户名 |
| operationType | 可选数字业务枚举；本次页面常用 1 控制、2 用户、3 参数、6 测试模式 |
| operationTarget | 可选业务设备编号，沿用原设备映射；不是任意文本搜索 |
| result | 可选，0 失败、1 成功 |

返回 `total,pageNum,pageSize,operationLogList`。记录包含原字段及新增 `uid,source_ip,session_id,tab_id,before_summary,after_summary,trace_id`。before/after 为 JSON 字符串或 null；session_id 为摘要管理标识，不是可登录的 Token。新请求审计与历史 operation_log 一起查询；历史缺失的字段保持 null，不补造数据。请求审计与原业务日志可能同时存在，应按事件来源/内容呈现，不假定一次操作只对应一行。

- 导出：`GET /api/history/export`，角色 3/4，使用与查询相同的筛选参数；最多 10000 条，超过需缩小时间范围。返回 CSV 文件及 `X-Audit-Id`；导出前会写审计，写入失败返回 503，不释放导出文件。
- 容量：`GET /api/history/status`，角色 3/4；返回 usagePercent、retentionDays、totalBytes（监测文件系统总空间）、usedBytes、writeFailed、capacityExceeded 等。
- 新结构化审计默认留存 180 天；旧 operation_log 不自动清理，`legacyRetentionManaged:false`。前端按 retentionScope 展示，不能显示为所有历史日志统一保留 180 天。
- writeFailed 是进程及本地文件锁存的告警，包含旧操作日志队列满/写失败；排障后由设备管理员清除，不因一次读取成功自动解除。

前端统一将 audit:read 和 audit:export 收紧为角色 3/4。旧 `/export_csv_stream` 仅保留指定日期命名的业务历史表导出，不能拿来导出用户表或替代新审计导出。

## 5. 证书、密钥与对端身份

### 5.1 CA 身份证书接口，角色 4

当前只支持外部 CA 签发。HTTPS、Modbus 主机、Modbus 从机分别使用独立私钥和 CSR，默认共用同一个 `[TLS] ca_file` 根信任包。不在设备保存 CA 私钥或本地签发叶证书。

| 功能 | 接口 | 说明 |
|---|---|---|
| 结构化证书/到期清单 | GET `/api/security/certificates` | master、slave、https 及 ca-root；中间链不重复计为设备身份 |
| 查看共享根信任 | GET `/api/cert/ca` | 返回根 CA SHA-256 指纹 |
| 导入根 CA | POST `/api/cert/ca/import` | FormData：file、fingerprint，每个根一项指纹；须通过可信渠道核对 |
| Modbus CSR | POST `/api/cert/csr` | JSON：role、name，可选 ip、dns，不再传 days |
| Modbus CSR 下载 | GET `/api/cert/csr/export?role=master` | slave 对应从机；通过 Bearer 下载 |
| Modbus 身份导入 | POST `/api/cert/identity/import` | FormData：role、file（叶证书）、chain（可选中间链） |
| Modbus 校验 | GET `/api/cert/check?role=master` | 校验完整链、用途、有效期和本机私钥 |
| Modbus 公开链导出 | GET `/api/cert/export?role=master` | 不含私钥 |
| HTTPS CSR | POST `/api/cert/https/csr` | CN/IP 从后端 INI 读取，前端不传设备私钥 |
| HTTPS CSR 下载 | GET `/api/cert/https/csr/export` | 下载供外部 CA 签发 |
| HTTPS 身份导入 | POST `/api/cert/https/identity/import` | FormData：file、chain；成功返回 reload_required |
| HTTPS 校验/续签状态 | GET `/api/cert/https/status` | 当前身份是否有效、待应用及续签状态 |
| HTTPS 应用 | POST `/api/cert/https/apply` | 后端固定脚本校验并应用，成功后才显示生效 |

主机证书为 clientAuth，从机/HTTPS 为 serverAuth，三者均须 CA:FALSE、digitalSignature。从机 SAN 必须覆盖实际 TCP 连接 IP；HTTPS SAN 覆盖 INI 的全部设备访问 IP。CSR 重复生成和续签保留原私钥；密钥丢失时拒绝自动换身份。

证书列表的 validityStatus 表示有效期，chainVerified 表示公共链校验；链失败时 status 为 invalid。privateKeyVerified:null 表示列表未做持钥自检，需显式 check。revocationStatus:unavailable 表示未接入 CRL/OCSP，不能展示“未吊销”。

原 generate、renew、trust-add、trust-remove、trust-list 接口返回 410 / CA_CSR_REQUIRED，前端删除直接生成证书、叶证书钉扎信任和本地续签交互。`/api/security/certificates/import` 保留为 Modbus 身份导入别名；不再支持 POST 创建或 DELETE 钉扎证书。

流程为“生成 CSR → 导出交外部 CA → 导入根信任与签发叶证书/中间链 → 校验 → 应用/维护重启”。Modbus 成功导入仍需重启 tems，HTTPS 导入不等于 Nginx 已 reload。临近到期任务只更新待签 CSR 和告警；签发需外部 CA 完成。初次缺少签发 HTTPS 证书时需通过本地终端引导，不能依赖未开通的 HTTPS 页面。

### 5.2 密钥及对端

- `GET /api/security/keys`（角色 4）：返回证书公钥 Key ID，以及在设备 CLI 可用时的 TEE RSA 公钥标识与已审计轮换时间；不会生成或轮换密钥。设备能力缺失返回 teeStatus:unavailable；对称密钥状态尚无底层遥测。
- `GET /api/security/peer-status`（角色 3/4）：当前 CA 模式返回 `data:[],liveAuthenticationTelemetryAvailable:false`，尚未提供实时对端身份与握手遥测；空数组不能显示成“没有连接”或“没有可信设备”。
- 现有 `GET /api/cert/tee/public-key`、`POST /api/cert/tee/keys`、`POST /api/cert/tee/rotate-rsa` 保留。页面初始化只做查询；生成/轮换是明确的管理员维护操作，不自动调用。

## 6. 安全状态、资源、网络与组件清单

| 功能 | 接口 | 前端使用 |
|---|---|---|
| CPU | GET `/api/system/cpu-usage` | usedPercent、sampleSeconds，已登录可读 |
| 内存 | GET `/api/system/memory-usage` | total、available、used、usedPercent，字节单位，已登录可读 |
| 磁盘与 CPU | GET `/api/system/disk-usage?path=/mnt/nvme` | 容量字节值及 display 显示值，已登录可读；磁盘不是审计日志容量 |
| 安全状态汇总 | GET `/api/security/status` | 角色 3/4；checks 各项独立带 available，成功采集的数据在 data；含维护状态 |
| 网口/路由/规则 | GET `/api/security/network-rules` | 角色 3/4；interfaces、routes、rules；依赖 ip/nft 命令与权限，以 interfacesAvailable/rulesAvailable 判断 |
| 安全配置摘要 | GET `/api/security/config-summary` | 角色 3/4；用户角色、能力、口令/会话策略、证书引用、审计、网络与组件信息，不包含密码/私钥 |
| 组件清单 | GET `/api/system/components` | 已登录可读；components 数组，包含 Python 包、内核、运行时和部署提供的补充清单 |

安全状态包含 CPU、内存、磁盘、登录容量、连接容量、审计、证书有效期、INI 完整性、时间同步采集结果。未采集成功显示“不可用”，不要将 ok:true 理解为全部检查通过。TEE 整体安全自检仍需平台提供。

network-rules 为只读内核快照，不是规则编辑接口；rulesAvailable:false 表示未采集成功，不表示没有规则或防火墙已关闭。配置摘要可导出 JSON；组件列表可导出 CSV/JSON。`firmwareInventoryComplete:false` 表示未配置完整平台组件补充清单，不能宣称是整机完整 SBOM。

首页/系统页补资源仪表；页面离开后停止轮询，对 RATE_LIMITED 降频。阈值告警使用实际数据，前端自设阈值需与后端告警区分。

## 7. 备份、恢复、出厂与应用身份清除

以下均要求角色 4。采用保守兼容方案：**默认只允许备份、查询、校验和执行预览；恢复/出厂/清除执行开关默认关闭**。前端必须先展示范围和预览，再进行明确操作确认。

### 7.1 当前备份范围

包含应用账号及角色、UID/启停和口令历史、安全设置、设备 INI、证书指纹引用；不备份可重放的登录 Token，不导出 TEE/证书私钥。备份为设备绑定的 AES-GCM 加密文件，同时返回 SHA-256；只允许同设备、同格式版本及兼容用户表结构恢复，证书引用变化时拒绝恢复。

**当前不包含业务历史数据库、平台镜像和整机文件系统**。前端页面明确显示 scope，不将此功能命名为“整机全量备份”。默认最多 20 个文件、目录总量 128 MiB、单文件约 16 MiB；达到限制提示设备管理员归档。

| 功能 | 接口 | 请求 / 返回 |
|---|---|---|
| 创建 | POST `/api/security/backups` | `{}`；201，返回 id、sha256、bytes、createdAt、scope、encrypted |
| 列表 | GET `/api/security/backups` | data[]：id、bytes、createdAt |
| 下载 | GET `/api/security/backups/{id}/download` | 加密 .lcb 文件，响应头 X-Backup-SHA256；带 Bearer 下载 |
| 校验 | POST `/api/security/backups/{id}/validate` | `{"sha256":"创建时的摘要"}`；返回兼容性、范围、摘要 |
| 恢复预览 | POST `/api/security/backups/{id}/restore` | `{"dry_run":true,"sha256":"摘要"}`；返回 validation、executionEnabled、会话失效及重启提示 |
| 执行恢复 | 同上 | dry_run:false、sha256、password、confirm:"RESTORE_BACKUP"；需执行开关与有效维护模式 |

执行前重新验密；校验不通过不恢复。恢复前自动创建检查点，成功后全部登录会话失效；前端提示重新连接和登录。返回 restart_required:true 时还需设备侧重启与健康检查，不能显示已完成整机安全验收。

### 7.2 恢复出厂

`POST /api/security/factory-reset`，`{"dry_run":true}` 预览。无设备管理员预置的固定出厂备份 ID/SHA-256 时返回 409 / FACTORY_BASELINE_NOT_CONFIGURED，前端提示“未配置出厂基线”，不自行选择某个普通备份。

执行请求：dry_run:false、password、confirm:"FACTORY_RESET"；同样要求执行开关和维护模式。基线必须使用强摘要口令；恢复后要求首次改密。范围仍是应用安全数据，不是平台镜像恢复。

### 7.3 应用身份清除

`POST /api/security/decommission`，默认 `{"dry_run":true}`，返回 plan，包含 scope、tables、privateFiles、excluded、completeDeviceErasure。

本轮保守实现范围为 **application-identities**：清除应用账号、会话、安全状态/设置及本地临时凭据、备份文件，保留业务数据、设备 INI、证书、平台/TEE 密钥、审计和应用日志。plan.completeDeviceErasure 为 false，前端名称用“应用身份清除”，不能显示“整机退役擦除已完成”。

执行请求：dry_run:false、scope:"application-identities"、password、confirm:"DECOMMISSION_APPLICATION"；要求执行开关和维护模式。操作后应用需要设备管理员重新配置账号；失败时显示错误码及 trace_id，联系设备管理员核查，不宣称全部成功；全局错误处理当前不保留 failedScopes。

## 8. 参数和网络页面的前端工作

- 参数下发仍调用 `POST /api/paraConfig/modifyParams`，字段 deviceid、address、value；角色 2/3/4。
- `GET /ini/all` 继续提供运行配置，密码、私钥、Token 等敏感字段已移除；前端不依赖这些字段，也不把缺失值写成空口令。
- INI 更新实际为 `POST /ini/update`，不是 `/api/ini/update`；角色 2/3/4，沿用现有 payload，成功后可能调度设备重启，需先确认并提示重连。
- 网口设置仍调用 `POST /network/set_ip`，字段 iface、ip、netmask、gateway，支持对象/数组；iface 为 net1–net4，只有 net1 网关生效。
- INI 更新已增加服务端校验：PCS 数量 0–4、BMS 数量 0–10；系统数量 1–2、子系统数量 1–4，测控条目最多 10 项；边界与当前设备 app_config.h 对齐；设备条目 ID 不重复，IP 为有效单播 IPv4，端口 1–65535，P2P 开关必须为布尔。其他字段按现有契约，不提交未知字段。
- 前端仍补设备实际容量、参数类型/范围、IP/掩码/端口格式、网关同网段与重复地址校验。保留端口和设备范围按双方确认的设备定义，不自行编造。
- 旧 GET `/api?sql=...` 已停用，返回 410 / SQL_ENDPOINT_DISABLED。页面不得继续发送 SQL；使用具体业务 API。POST `/api` 的兼容请求限功能码 3/4/6、最多 100 组、每组最多 125 个寄存器；写请求受参数权限限制。

## 10. 接口入参与返回格式（联调契约）

以下按当前路由及全局响应处理代码核对，补充前文功能表。除明确标注外，成功 HTTP 200；GET 不带 body，POST 使用 `Content-Type: application/json`。下表使用 TypeScript 风格的**结构说明**，不是可直接发送的 JSON：`?` 表示可选，`T | null` 表示允许空值，`T[]` 表示数组，`number` 为 JSON 数值。标注 JSON 的代码块才是请求/响应示例。所有示例中的账号、IP、摘要和时间均为示意。

### 10.1 公共请求与错误响应

| 位置 | 字段 | 必填与含义 |
|---|---|---|
| Header | Authorization | 受保护接口必填，`Bearer <session_token>`；登录、GET login-notice 例外 |
| Header | X-CSRF-Token | 已认证写请求必填，使用登录/session 返回值 |
| Header | X-Tab-Id | 可选，最多 64 个字母、数字、下划线或连字符 |
| Header | Content-Type | JSON 为 application/json；FormData 由浏览器自动设置 |
| Response Header | X-Trace-Id | 请求追踪编号，用于报错定位 |
| Response Header | X-Audit-Id | 已成功记审计时返回；不要假定每个响应都有 |

HTTP 4xx/5xx 由全局处理器规范化，实际返回如下，**不是各路由内部原始 error/details 对象**：

```json

```

登录失败可额外带 `attempts_remaining:number`、`lock_seconds:number`，容量错误可带 `loginSessions:object`。其他错误附加字段当前不会保留到线上响应；例如清除失败时不能依赖 `failedScopes`，网络部分失败时不能依赖 `errors[]`，应显示失败及 trace_id，并查询实际状态/联系设备管理员核查。5xx 的 message 固定为通用提示。HTTP 200 的旧业务接口仍须检查自身业务成功字段。

本节所有 JSON 成功响应均使用外层 **`{status:3,message:string,data:下表结构}`**，HTTP 200；不要查根对象的 ok/role。下载例外。全部要求角色 4。role 仅 master/slave；HTTPS 使用独立 URL。

| 接口 | 入参及限制 | 成功 data |
|---|---|---|


```json

```

```typescript

  reason:null|"expiring"|"missing_invalid_or_configuration_changed",
  csr?:string,sha256?:string,device_ips?:string[]}
```

renewal 来自最近一次定时检查，null 表示暂无记录，不等于不需续签；csr 是设备端路径，前端使用 CSR 下载 API，不将该路径当 URL。HTTPS 校验失败返回非 2xx，不会返回 `status:3,data:{valid:false}`。主要错误为 400 PKI_INVALID_REQUEST、422 PKI_VALIDATION_FAILED、503 PKI_UNAVAILABLE；HTTPS apply 失败为 503。旧生成/续签/钉扎路由为 410 CA_CSR_REQUIRED。

上传调用示例：

```javascript
const form = new FormData();
form.append('role', 'slave');
form.append('file', signedLeafFile);
if (intermediateChainFile) form.append('chain', intermediateChainFile);
const response = await fetch('/api/cert/identity/import', {
  method: 'POST',
  headers: {Authorization: `Bearer ${sessionToken}`, 'X-CSRF-Token': csrfToken},
  body: form
});
const body = await response.json();

// body.data.restart_required 为 true；页面提示维护重启后生效。
```

```typescript
  keyId:string,signatureAlgorithmOid:string,status:string,validityStatus:string,
  chainVerified:boolean,privateKeyVerified:null,validityOnly:false,
  revocationStatus:"unavailable"}
// 文件损坏时条目只有 {role:string,status:"invalid",reason:string}；缺少文件不生成条目。

```

notBefore/notAfter 为带时区 ISO 8601；validityStatus 为 valid/expiring/expired/not_yet_valid，status 还可为 invalid。TEE 这些既有接口不带 Modbus role 参数，不能当作分别轮换主机/从机私钥的接口。

### 10.8 备份、恢复、出厂与清除

以下 `{id}` 为创建/列表返回的 32 位小写十六进制标识，不是路径。摘要为 SHA-256 十六进制字符串。所有接口角色 4。

| 接口 | 入参 | 成功返回 |
|---|---|---|
| POST `/api/security/backups` | `{}` | HTTP 201，`{ok:true,id:string,sha256:string,bytes:number,createdAt:string,scope:string[],encrypted:true}` |
| GET `/api/security/backups` | 无 | `{ok:true,data:{id:string,bytes:number,createdAt:string}[]}` |
| GET `/api/security/backups/{id}/download` | Path id 必填 | application/octet-stream，加密附件 backup-{id}.lcb，Header X-Backup-SHA256 |
| POST `/api/security/backups/{id}/validate` | `{sha256?:string}`，建议必传预期摘要 | `Validation` |
| POST `/api/security/backups/{id}/restore` | 预览 `{dry_run:true,sha256?:string}`；执行 `{dry_run:false,sha256:string,password:string,confirm:"RESTORE_BACKUP"}` | 预览 `{ok:true,dry_run:true,validation:Validation,sessions_will_be_revoked:true,restart_required:true,executionEnabled:boolean}`；执行 `RestoreResult` |
| POST `/api/security/factory-reset` | 预览 `{dry_run:true}`；执行 `{dry_run:false,password:string,confirm:"FACTORY_RESET"}` | 预览 `{ok:true,dry_run:true,validation:Validation,scope:"application-security",restart_required:true}`；执行 `RestoreResult` |
| POST `/api/security/decommission` | 预览 `{dry_run:true}`；执行 `{dry_run:false,scope:"application-identities",password:string,confirm:"DECOMMISSION_APPLICATION"}` | 预览 `{ok:true,dry_run:true,plan:Plan,executionEnabled:boolean}`；成功执行 `{ok:true,plan:Plan,failedScopes:[],reprovisionRequired:true}` |

```typescript
Validation = {ok:true,id:string,sha256:string,compatible:true,scope:string[],createdAt:string}
RestoreResult = {ok:true,checkpoint:string,restart_required:true,sessions_revoked:number,
  healthCheck:"requires-restart-and-device-check"}
Plan = {scope:"application-identities",tables:string[],privateFiles:["credentials","backups"],
  excluded:string[],completeDeviceErasure:false}
```

scope 数组当前为 application-accounts、security-settings、device-ini、certificate-references。createdAt 为带时区 ISO 8601；bytes 为文件字节数。Plan.tables 使用部署实际表名，前端原样展示；excluded 为 platform-and-TEE-keys、device-configuration、certificates、business-database、audit-and-application-logs。

仅 JSON 布尔 `dry_run:false` 才进入执行分支；省略默认预览。执行还需服务端开关、有效维护模式和当前管理员重新验密。400 常见 code 为 DESTRUCTIVE_OPERATIONS_DISABLED、CONFIRMATION_REQUIRED、MAINTENANCE_REQUIRED、REAUTHENTICATION_FAILED、VALIDATED_DIGEST_REQUIRED、EXPLICIT_SCOPE_REQUIRED；409 FACTORY_BASELINE_NOT_CONFIGURED/FACTORY_BASELINE_REQUIRES_STRONG_CREDENTIALS；404 BACKUP_NOT_FOUND/RESOURCE_NOT_FOUND；503 AUDIT_UNAVAILABLE。失败统一遵循 10.1，不将预览成功显示为执行完成。

| 接口 | 入参 | 成功返回 |

| POST `/api/paraConfig/modifyParams` | JSON 或表单：deviceid（整数或整数字符串）、address（整数或整数字符串）、value（非空整数字符串）；三个字段必填，值范围按寄存器配置 | `{success:true,msg:"Successfully sent"}`；该旧接口也可能 HTTP 200 返回 `{success:false,msg:string}` 或 `{code:1,msg:string}`，须判 success===true |

```typescript

  pointToPointEnabled?:boolean,bmsBrand?:number,pcsBrand?:number,
  pcsList?:DeviceEntry[],bmsList?:DeviceEntry[],testCtlList?:DeviceEntry[]}
DeviceEntry = {id:number,ip:string,port:number}
NetworkUpdate = {id?:string|number,iface:string,ip:string,netmask:string,gateway?:string}
NetworkResult = {id:string|number|null,iface:string,cidr:string,ip:string,netmask:string,
  gateway:string|null,config_path:string,ini_path:string|null,
  schedule_error:null,ini_error:null,ok:true}
```

IniUpdate 中 mainSystem 1–2、subSystem 1–4、pcsCount 0–4、bmsCount 0–10、品牌 0–65535；pcsList/bmsList/testCtlList 上限分别 4/10/10，条目 id 范围分别 1–4/1–10/1–10、同列表不能重复，port 1–65535。数值项兼容十进制整数字符串，布尔项只接受布尔。部分更新仅提交要修改的字段；运行配置不能整个透传到此接口。system 为 INI 键名到整数值的映射；pcs/bms/measure 元素为 DeviceEntry；品牌数组元素为 `{bms1_brand:品牌整数}` 或 `{pcs1_brand:品牌整数}` 等对应键值。它们是写入摘要，不用于判断重启完成。

NetworkUpdate 的 iface 为 net1–net4；ip/netmask 为有效 IPv4/掩码，gateway 仅 net1 生效。网络和 INI 更新可能先写入配置再在后续步骤失败，收到非 2xx 不代表完全未修改，重新连通后读取状态核对，不盲目自动重试。operatorName 无需前端提交，审计操作人由服务端会话决定。

本节为本反馈涉及接口的数据契约；旧 SQL 查询入口仍为 410，不作为页面数据源。证书详细部署流程另见 [CERT_API.md](CERT_API.md)，后端运行配置见 [SECURITY_CENTER.md](SECURITY_CENTER.md)。

兼容寄存器接口 `POST /api`：JSON 必填 `deviceid,functioncode,Address,Quantity`，均为逗号分隔的十进制整数字符串（注意 Address/Quantity 首字母大写）；写入功能码 6 时另传同样格式的 value。四个必填字段元素数量一致，1–100 组；deviceid 1–247，functioncode 3/4/6，Address 0–65535，Quantity 1–125 且不越过地址上界；功能码 6 的 Quantity 必须 1，value 数量与组数相同，值为 -32768–65535。每个字符串不超过 1000 字符。该接口返回 JSON 文本数组，旧实现未明确设置 application/json，客户端需按 JSON 解析：

```json
[{"deviceid":"1"},{"functioncode":"3"},{"Address":"100"},{"Quantity":"2"},{"Registers":"10,20"}]
```

Registers 中同组读值逗号分隔、组间冒号分隔；写入结果为 `ok(地址)`、`error(地址)` 或 `exception(地址)`，不能只看 HTTP 200 判断写成功。新页面优先使用具名业务接口。
