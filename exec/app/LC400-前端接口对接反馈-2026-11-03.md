# LC400 前端接口对接反馈与功能分工

日期：2026-11-03  
对应文档：《LC400-4-2前端差距核验与后端接口清单》第四、第五章。

以下按当前后端工作区代码整理，供前端调整调用与安排联调。“已有接口”表示代码已实现，不代表目标设备已部署或联调通过。前后端交付时需核对同一版本。

当前登录已经返回真实 `session_token`；会话撤销、审计跨日查询、Modbus 证书管理、TEE 密钥操作及部分资源监测均已有基础。请优先复用下列实际接口。清单中尚未实现的接口集中列在第 7 节，相关页面暂不显示为功能已完成。

## 1. 通用调用约定：前端优先完成

### 1.1 登录态与请求头

- 当前认证方式是 **Bearer Token**，不使用登录 Cookie，也不是 JWT。
- 登录成功后，将 `session_token`、`csrf_token`、`expires_at` 和身份信息保存到当前标签页的 `sessionStorage` 或内存。
- 移除 `session_token || token || "ok"` 以及环境变量占位 Token。未取得有效 `session_token` 时不进入已登录状态。
- 刷新页面后调用 `GET /permission/session`，以服务端返回的用户名、角色更新界面。
- 除登录与静态页面外，业务请求需携带 Bearer。
- 下载使用带认证头的请求获取 Blob，不把 Token 拼到 URL；上传使用 FormData，由浏览器生成 multipart boundary。

```http
Authorization: Bearer <session_token>
X-CSRF-Token: <csrf_token>
```

GET/HEAD 只需 Authorization。建议其他方法统一携带 X-CSRF-Token；同源来源信息也可通过现有来源检查，但不能替代 Bearer。前端通过同源 HTTPS 入口访问；本地开发使用同源代理，当前未开放跨域前端调用。

同页切换账号/重新登录时可携带本页旧 Bearer，后端只替换该凭据对应的会话；新标签页没有凭据时重新登录。不要用 localStorage 或跨页广播覆盖其他页身份。浏览器复制标签页可能复制 sessionStorage，不能仅凭存储位置宣称“一标签一会话”；同一个 Token 的页面共享同一服务端会话。

### 1.2 失效、退出与连接

| 情况 | 前端处理 |
|---|---|
| 登录接口 401 | 提示凭据错误，不套用业务会话过期提示 |
| 业务接口 401 / SESSION_INVALID | 清理发出该请求时的本页登录态并返回登录页；忽略已经被新登录替换的旧请求响应 |
| 403 | 提示无权限或请求校验失败，不统一当作退出登录 |
| 429 / LOGIN_LIMIT_REACHED | 提示登录会话数已满；不是密码错误次数锁定，不显示虚构的解锁倒计时 |
| 503 | 提示服务暂不可用并允许重试，不当作密码错误 |
| 主动退出 | 调用 POST `/permission/logout`，成功或已返回 401 后清理本页状态并断开 Socket.IO；其他失败提示退出未完成 |

当前默认会话有效期是登录后固定 1800 秒，以登录响应的 `expires_at`（Unix 秒）为准；正常访问不续期。不要把它显示成“空闲倒计时”。后端尚未提供空闲超时、维护模式截止时间或失败锁定剩余秒数。

Socket.IO 握手传 `auth: { session_token }`，重连时读取当前 Token；切换账号后断开旧连接再重连，退出时主动断开。已有连接仅在握手时认证，前端不能依赖 WebSocket 持续连接判断登录仍有效。

### 1.3 响应适配

当前响应尚未统一，前端需按接口适配，不要将所有接口都限定为 `ok === true` 或 `status === 0`：

- 权限接口通常使用 `ok`。
- 审计查询直接返回 `total/pageNum/pageSize/operationLogList`。
- 证书、TEE 成功通常为 HTTP 200、`status: 3`，内容在 `data`。
- 未统一的错误可能位于 `error`、`message` 或 `msg`；页面用友好的错误提示，不直接展示堆栈、SQL、系统路径等原始异常。后端仍需修复异常脱敏。

## 2. 登录、账号及会话管理

| 前端功能 | 方法与接口 | 请求与响应要点 | 状态 |
|---|---|---|---|
| 登录 | POST `/permission/login` | JSON：`username,password`；成功返回 `ok,session_token,csrf_token,expires_at,username,permission,first_login,password_expired,password_warning,password_expire_at,password_days_left` | 可对接 |
| 刷新后恢复身份 | GET `/permission/session` | 返回 `ok,username,permission,csrf_token`；不重新下发原始 Token | 可对接 |
| 本页退出 | POST `/permission/logout` | 无必需业务请求体；成功 `ok:true`，只撤销当前会话 | 可对接 |
| 管理员会话列表 | GET `/permission/sessions` | `sessions[]`：`session_id,username,expires_at,expired,current` | 角色 4 可对接 |
| 强制下线一个会话 | POST `/permission/sessions/revoke` | JSON：`{"session_id":"列表中的标识"}`；返回 `ok,session_id,username` | 角色 4 可对接 |
| 用户列表 | POST `/permission/all` | 可发送 `{}`；返回 `ok,count,data[]`，含用户名、角色及口令生命周期字段 | 已有，后端需补授权及脱敏 |
| 新增用户 | POST `/permission/add` | JSON：`username,permission`；permission 为 1–4 | 已有，后端需补授权与初始口令策略 |
| 修改用户/密码 | POST `/permission/update` | `username` 为目标账号；可选 `new_username,password,permission,first_login` | 已有，后端需补管理/本人修改的授权规则 |
| 删除用户 | POST `/permission/delete` | JSON：`username` 为目标账号 | 已有，后端需补授权 |
| 锁屏验密解锁 | POST `/permission/verify` | 尚无接口 | 待后端；不能将 `/permission/session` 当作验密 |
| 随机临时口令重置 | POST `/permission/reset-password` | 尚无接口 | 待后端 |
| 普通账号启用/禁用 | 清单计划扩展 `/permission/update` | 当前不支持 `enabled/status` | 待后端 |

前端需要落实：

1. 删除占位 Token；将登录返回的真实凭据接入全部请求与 Socket.IO。
2. 根据 `first_login/password_expired/password_warning` 实现首次改密、到期提示及页面引导。当前服务端未强制限制过期账号业务访问，该缺口由后端处理。
3. 会话管理页按“会话”列出记录，不按 username 合并成一个在线账号。`session_id` 是管理标识，不能作为 Bearer 使用；过期记录可能尚未清理，不等于在线标签数。
4. 强制下线使用 `/permission/sessions/revoke`，不要发送清单中的 `logout + force:true,username`；目前没有“一次退出该账号全部会话”的契约。
5. 用户页不显示、不缓存、不导出响应中的 `password` 字段。后端将另行移除该哈希字段并补权限；前端隐藏按钮不能替代后端授权。
6. UID、last_login、账号启停状态、失败次数/锁定时间无数据时显示“暂未提供”，不能用用户名、当前时间或本地计数冒充。

## 3. 审计查询与导出

已有：`GET /api/history/getOperationlog`。

```text
/api/history/getOperationlog?beginDt=2026-11-01T00:00:00&endDt=2026-11-03T23:59:59&pageNum=1&pageSize=20
```

| 参数 | 说明 |
|---|---|
| beginDt/endDt | 必填，设备本地日期时间，支持跨日；格式 `YYYY-MM-DDTHH:mm:ss` 或空格分隔；当前不接收带 Z 的 ISO 字符串 |
| pageNum/pageSize | 正整数；前端限制合理页大小并校验开始时间不晚于结束时间 |
| operator | 可选，操作用户名 |
| operationType | 可选整数；本次对接涉及：1 控制、2 用户、3 参数、6 测试模式 |
| operationTarget | 可选，后端按设备编号解析，不是任意文本目标搜索 |
| result | 可选，0 失败、1 成功 |

返回 `total,pageNum,pageSize,operationLogList`；记录字段为 `log_id,operation_time,operator,operation_type,operation_target,sort,result,remark`。

前端需接入跨日筛选、分页与上述字段。注意请求的 operationType 为数字，响应 operation_type 可能为业务枚举字符串，不要直接套用同一种类型。

尚缺 `source_ip,session_id/tab_id,before_summary,after_summary` 和审计容量/留存状态；对应列或卡片显示未提供。`GET /api/history/status` 尚未实现。

现有 `GET /export_csv_stream?table=...` 是通用数据表导出，不具备清单要求的审计筛选、专门授权、导出写审计能力，不能用它宣布审计导出完成。前端可准备导出界面和权限入口；正式审计导出闭环需后端补齐。`audit:read/export` 的角色范围仍需统一，不能以当前后端未拦截作为授权依据。

## 4. Modbus 证书与密钥页面

以下管理的是 **Modbus TLS 证书**，不是浏览器访问设备时的 HTTPS 证书。接口均要求管理员角色 4。清单中的 `/api/security/certificates*` 尚不存在，可先按本节对接现有功能。

| 前端功能 | 方法与接口 | 参数 / 返回 |
|---|---|---|
| 本机证书信息 | GET `/api/cert/identity?role=master` | role 必填 master/slave；`data.certificate` 是文本 |
| 校验证书 | GET `/api/cert/check?role=master` | 成功 `data.valid:true`；校验不通过可返回 422、`data.valid:false` |
| 首次生成 | POST `/api/cert/generate` | JSON：`role,name`；可选 `days,ip,dns` |
| 更新已有证书 | POST `/api/cert/renew` | 同生成参数；不等于轮换私钥 |
| 信任证书列表 | GET `/api/cert/trust-list` | `data.output` 为文本，当前不是结构化数组 |
| 导入可信主机证书 | POST `/api/cert/trust-add` | FormData：`file`（.crt、最大 1 MiB），可选完整 SHA-256 `fingerprint` |
| 移除可信主机证书 | POST `/api/cert/trust-remove` | JSON：`fingerprint`；不是 DELETE，也不按文件名删除 |
| 下载本机公开证书 | GET `/api/cert/export?role=master` | 返回证书文件，用带 Bearer 的 Blob 下载 |

生成/更新请求示例：

```json
{"role":"slave","name":"slave-001","days":365,"ip":["192.168.2.136"],"dns":[]}
```

`days` 为 1–3650 整数；`name` 为 1–64 字符，以字母/数字开头，其余限字母、数字、下划线、点、连字符。证书文本按普通文本展示，不使用 HTML 渲染。收到 `restart_required:true` 时提示需要按维护流程生效，不能显示已自动重启完成。

顶部“即将到期”汇总条、独立颁发者/有效期/Key ID 列，仍依赖后端补结构化字段；不要将脚本输出解析成未经约定的长期接口。

TEE 可复用接口：

| 功能 | 接口 | 说明 |
|---|---|---|
| 查询 RSA 公钥 | GET `/api/cert/tee/public-key` | 返回 `data.algorithm,format,modulus,exponent`，不是 PEM，后两者为 Base64 |
| 创建或复用持久密钥 | POST `/api/cert/tee/keys` | JSON：`{"type":"aes"}` / rsa / all；不是列表查询，也不会轮换已有密钥 |
| 轮换 RSA 密钥 | POST `/api/cert/tee/rotate-rsa` | JSON：`{"confirm":"ROTATE_RSA_KEY"}`；仅在明确维护操作确认后调用，成功后提示证书更新/重启要求 |

不要在页面初始化时调用密钥生成或轮换。清单所需 Key ID、最近轮换时间、密钥状态列表仍待 `GET /api/security/keys` 或等价结构化接口；公钥查询成功不能代表整个安全系统自检通过。

## 5. 资源仪表与安全状态

| 前端功能 | 已有接口 | 使用方式 |
|---|---|---|
| CPU 仪表 | GET `/api/system/cpu-usage` | 返回 `usedPercent,sampleSeconds` |
| 磁盘与 CPU 仪表 | GET `/api/system/disk-usage?path=/mnt/nvme` | 返回 `total,used,free,usedPercent,cpu,display`；省略 path 默认 `/` |
| 登录容量 | 登录成功或 GET `/permission/session` | `loginSessions.limit/active/remaining`，当前上限 20 |
| 主服务 Socket.IO 连接容量 | 登录成功或 GET `/permission/session` | `webConnections.limit/active/remaining`，当前单进程上限 20 |

磁盘原始容量单位为字节；`display.diskTotal/diskUsed/diskFree/diskUsage/cpuUsage` 可直接展示。磁盘值表示路径所在文件系统容量，不是审计日志容量。登录会话数、Socket.IO 连接数和用户数分别展示，不能互相替代。

前端可先在首页/系统页接入 CPU、磁盘和连接容量，采用适度轮询，离开页面后停止；请求失败显示不可用。内存、时间同步、统一告警、对端身份、安全功能总状态仍待后端，不能用其他指标推断为正常。前端自设阈值提示需标明为页面提示，不冒充后端安全告警。

## 6. 参数与网络配置页面

| 前端功能 | 接口 | 当前调用要点 |
|---|---|---|
| 参数下发 | POST `/api/paraConfig/modifyParams` | JSON：`deviceid,address,value`；后端已有部分类型/设备/角色检查，参数权限当前为 2/3/4 |
| 读取配置 | GET `/ini/all` | 复用现有配置契约；普通 INI 数据不等于安全配置摘要 |
| 修改配置 | POST `/ini/update` | 按现有页面 payload 契约；**路径没有 `/api` 前缀**，成功写入后会调度设备重启，应先确认并提示重新连接 |
| 设置网口 | POST `/network/set_ip` | 单对象或数组，字段 `iface,ip,netmask,gateway`；iface 为 net1–net4，网关仅 net1 生效 |

网络请求示例：

```json
{"iface":"net1","ip":"192.168.2.136","netmask":"255.255.255.0","gateway":"192.168.2.1"}
```

前端需补数量范围、IP/掩码/端口格式、网关同网段和请求内重复地址等校验；设备数量/参数范围以对应设备定义为准。保留端口与完整冲突规则需要双方约定，不能在前端自行编造。修改设备地址后提示使用新地址重连。

`GET /api/security/network-rules` 尚未提供，现有网口配置不包含完整防火墙/白名单规则；不能把“网口配置成功”展示成“安全规则已生效”。后端需补配置接口授权和完整参数校验，前端校验不替代服务端检查。
