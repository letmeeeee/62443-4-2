# LC400 前后端联调反馈：PKI 模式变更

日期：2026-11-16。本文按当前工作区实现整理，供前后端联调使用；不代表设备端已部署验收。

## 2026-11-17 补充：兼容修复，无需新增前端请求

恢复最初多批次并存规则，继续显式传递 batch_id，不自动合并或清理。已撤销
`POST /api/cert/reset`，无需对接该接口。现有请求路径和参数格式不变。
后端通过原 CRL 上传入口识别已确认指纹的暂存根，将新根的 CRL 暂存至匹配批次，
再通过原 custom/apply 统一安装，避免新根/CRL相互依赖。需先上传定制根，再上传 CRL。
通用根替换增加跨角色验证，暂存批次增加版本冲突检查，直接根签发证书自动去除
未显式指定的旧链，批次查询同步旧全局应用结果。
HTTPS 健康查询在身份异常时返回正常查询包装，data.valid=false 和 reason/detail；
不会自动生成 CSR。详见 [CUSTOM_PKI.md](CUSTOM_PKI.md) 的兼容修复说明，下文与此
不一致的历史描述以该说明为准。

## 1. 本次变更

新增定制 PKI 流程，支持外部提供设备私钥、CA 根、中间链和已签发证书。适用于 Modbus 主机、Modbus 从机、HTTPS 的 **file 后端**，无需先在设备生成 CSR。

| 项目 | 通用流程（模式1） | 定制流程（模式2） |
| --- | --- | --- |
| `pki_mode` | `general` | `trina` |
| 身份来源 | 设备持有私钥，生成 CSR 后导入签发结果 | 外部导入设备私钥和签发结果 |
| 接口 | 原有接口 | 新增 `/api/cert/custom/` 接口 |
| CSR 校验 | 保留原规则 | 不依赖 CSR，不生成 CSR |
| 生效方式 | 保留原行为 | 上传暂存，再统一调用定制应用接口 |
| 外部身份异常或临近过期 | — | HTTPS 自动维护只报告，不自动生成 CSR 或替代密钥 |

`pki_mode` 是**请求流程参数**，不是设备全局开关，不写入 INI，没有新增“切换整机模式”接口。旧入口不因设备已有定制身份而整体禁用；显式调用旧 CSR 接口仍然允许，但必须使用 `general`。给旧接口传 `trina` 不能绕过 CSR 校验。

旧接口缺省 `pki_mode` 时仍按 `general` 处理，兼容既有调用方。TEE、其他业务接口及业务报文格式不在本次调整范围内。配套 file 密钥代码默认生成 RSA-2048，同时兼容 RSA-2048/3072；现有 3072 密钥不会因此自动替换。

## 2. 前端需要调整的地方

1. 证书管理页面增加“通用 / 定制”流程选择，提交值分别为 `general` / `trina`，不是数字或中文。
2. 通用流程继续现有 CSR 操作，旧请求建议显式附带 `pki_mode=general`；不要向所有业务请求统一注入此参数。
3. 定制流程提供角色选择：`master`（Modbus 主机）、`slave`（Modbus 从机）、`https`。共享 CA 根不区分角色。
4. 增加私钥、CA 根、中间链、已签发叶证书上传；根上传同时填写可信渠道取得的完整 SHA-256 指纹。提供“无中间链 / 清除原中间链”选项。
5. 首次上传后保存 `data.batch_id`，后续上传、应用、查询必须复用该编号。首次上传完成前不要并行发起多个无编号上传。
6. 上传成功提示“已暂存，尚未生效”，增加独立“校验并应用”按钮。它调用 `/api/cert/custom/apply`，不能调用旧 `/api/cert/https/apply` 来发布定制材料。
7. 按 `data.status` 显示暂存、已安装待完成服务应用、已生效三种状态。应用失败后查询批次状态，并为待完成服务提供重试应用操作。
8. HTTPS 应用可能导致连接中断；超时后先用原批次编号查状态，不能直接认定失败并新建批次。
9. 外部身份异常、缺失或临近过期时提示“需外部重新签发并导入”，不要自动触发 CSR 接口。
10. 区分成功 JSON、统一错误 JSON 和文件下载响应；成功判断不能统一依赖 `ok=true`。

批次编号可保存在 sessionStorage 用于中断恢复；私钥文件内容不得写入浏览器持久存储、控制台日志或埋点。当前状态接口必须提供批次编号，不能用来枚举所有历史批次。

## 3. 公共约定

### 3.1 认证与参数位置

接口沿用管理员 Session/Bearer 权限要求。POST 建议统一携带同一次登录获得的 CSRF Token：

```http
Authorization: Bearer <session_token>
X-CSRF-Token: <csrf_token>
```

非同源客户端（例如 Apifox）POST 缺少 CSRF Token 可能在全局认证层被拦截，尚未进入证书路由。GET 不进行同样的 CSRF 校验；同源 POST 可通过原有来源检查。

| 请求类型 | `pki_mode` 位置 |
| --- | --- |
| GET | URL query |
| POST JSON | JSON body |
| POST 文件上传 | multipart/form-data 文本字段 |

浏览器使用 FormData 时不要手工设置 multipart 的 Content-Type/boundary。新上传接口要求单个文件非空且不超过 **1 MiB**；清除中间链不上传文件。

### 3.2 模式校验

| 接口族 | 允许值 | 未传 |
| --- | --- | --- |
| 原有通用证书接口及安全中心导入/验证别名 | `general` | 默认 `general` |
| 新增定制接口 | `trina` | HTTP 400 |

非法枚举或接口与模式不匹配返回 HTTP 400、`PKI_INVALID_REQUEST`。

## 4. 新增定制接口

以下路径均相对于设备地址，例如 `https://<设备地址>`。

### 4.1 上传接口总表

四个上传接口均为 **POST multipart/form-data**，只暂存，不立即覆盖当前生效身份。

| 路径 | 必填字段 | 可选字段 |
| --- | --- | --- |
| `/api/cert/custom/key/import` | `pki_mode=trina`、`role`、`file` | `batch_id` |
| `/api/cert/custom/ca/import` | `pki_mode=trina`、`file`、`fingerprint` | `batch_id` |
| `/api/cert/custom/chain/import` | `pki_mode=trina`、`role`、`file` 或 `clear=true` | `batch_id` |
| `/api/cert/custom/identity/import` | `pki_mode=trina`、`role`、`file` | `batch_id` |

字段说明：

| 字段 | 类型 / 格式 | 规则 |
| --- | --- | --- |
| `pki_mode` | 文本 | 固定 `trina` |
| `role` | 文本枚举 | `master` / `slave` / `https`；根接口不传 |
| `batch_id` | 文本 | 首次可省略；返回值是 32 位小写十六进制编号 |
| `file` | 文件 | 根据接口分别为私钥、根、中间链、叶证书 |
| `fingerprint` | 可重复文本字段 | 每个根的完整 SHA-256，64 位十六进制，可带冒号；多个根重复同名字段，不传 JSON 数组 |
| `clear` | 文本 | 仅中间链接口支持精确值 `true`，此时必须没有 `file` |

材料要求：

- **私钥**：单份未加密 PEM RSA-2048/3072 设备私钥，支持 PKCS#8 或 RSA 私钥格式。不是 CA 私钥；不支持 PFX、加密 PEM、TEE。三个角色必须使用不同密钥。
- **CA 根**：PEM 根集合，指纹必须与可信渠道提供的根集合完全一致，不能只填写截断指纹。
- **中间链**：PEM，按叶证书签发者到上级 CA 的顺序排列，不混入根证书。直接由根签发时使用 `clear=true`；不上传空文件。
- **叶证书**：单份已签发设备证书，不能把私钥或完整链拼入此文件；中间链通过单独接口上传。

未修改的材料可复用设备当前生效材料；更换私钥时必须提供匹配的新叶证书。只换叶证书而不上传中间链会保留现有链，若要去掉原链必须显式 `clear=true`。

### 4.2 参数示例

第一次上传私钥：

```text
POST /api/cert/custom/key/import
Body: form-data
pki_mode = trina
role     = master
file     = <设备私钥 PEM 文件，类型 File>
```

取得批次编号后上传共享根：

```text
POST /api/cert/custom/ca/import
Body: form-data
pki_mode    = trina
batch_id    = <首次上传返回的 batch_id>
fingerprint = <根1完整 SHA-256>
fingerprint = <根2完整 SHA-256，仅多根时重复>
file        = <CA根 PEM 文件，类型 File>
```

上传中间链：

```text
POST /api/cert/custom/chain/import
Body: form-data
pki_mode = trina
batch_id = <同一批次编号>
role     = master
file     = <中间链 PEM 文件，类型 File>
```

无中间链时改为以下请求，不携带 `file`：

```text
POST /api/cert/custom/chain/import
Body: form-data
pki_mode = trina
batch_id = <同一批次编号>
role     = master
clear    = true
```

上传叶证书：

```text
POST /api/cert/custom/identity/import
Body: form-data
pki_mode = trina
batch_id = <同一批次编号>
role     = master
file     = <已签发叶证书 PEM 文件，类型 File>
```

角色替换为 `slave` 或 `https` 即可上传相应身份。一个批次可同时包含多个角色和共享根；后续漏传 `batch_id` 会创建独立批次，不会自动按用户或角色合并。

### 4.3 统一校验并应用

**POST `/api/cert/custom/apply`**，Content-Type 为 application/json：

```json
{
  "pki_mode": "trina",
  "batch_id": "0123456789abcdef0123456789abcdef"
}
```

后端在应用时统一校验私钥匹配、完整信任链、有效期、CA:FALSE、密钥用途、角色 EKU 和现有 CRL 策略；上传成功不代表这些最终校验全部通过。

| 身份 | 额外要求 |
| --- | --- |
| master | clientAuth；沿用 Modbus CN 命名规则 |
| slave | serverAuth；沿用 Modbus CN 命名规则；必须有 IP SAN |
| https | serverAuth；CN 以 `LC400-` 开头（区分大小写）；IP SAN 覆盖当前 INI 的 HTTPS device_ips |

不接受同时包含客户端和服务端用途的双角色 EKU。Modbus CN 规则为 `[A-Za-z0-9][A-Za-z0-9_.-]{0,63}`。替换共享根还会检查其他已有身份，避免破坏其信任关系。

验证通过后备份旧材料（包括旧 CSR），安装新材料、撤下旧 CSR、记录外部身份来源，并应用相关服务：Modbus 使用 tems，HTTPS 使用现有 HTTPS/nginx 应用流程。

服务应用未全部成功时返回 HTTP 503、`CUSTOM_PKI_APPLY_FAILED`，新材料可能已经安装。查询状态后，使用**同一批次编号**重试 apply，仅重试未成功服务；不要向已安装批次重新上传材料。

### 4.4 查询批次状态

**GET `/api/cert/custom/status?pki_mode=trina&batch_id=0123456789abcdef0123456789abcdef`**

返回批次材料类型、状态和服务应用结果，不返回私钥或内部生效文件摘要。它是批次状态，不是实时证书健康检查，也不是整机模式查询。

| `data.status` | 前端文案 | 下一步 |
| --- | --- | --- |
| `staged` | 已暂存，未安装 | 可替换暂存材料，再应用 |
| `installed` | 文件已安装，服务应用未完成 | 查询 pending/services，处理后重试应用 |
| `applied` | 已生效 | 完成；修改材料需新建批次 |

已安装/已应用批次不能再次上传；重复应用已成功且未发生外部材料变更的批次可幂等返回。其他入口改变生效材料后，再应用旧批次可能返回 409，需要创建新批次。恢复日志未处理导致的 409 需管理员检查设备恢复流程，不能无限重试。

### 4.5 成功响应

HTTP 200，示例为首次上传私钥：

```json
{
  "status": 3,
  "message": "Custom PKI material staged; use custom apply to activate",
  "data": {
    "batch_id": "0123456789abcdef0123456789abcdef",
    "pki_mode": "trina",
    "status": "staged",
    "roles": {"master": ["key"]},
    "ca": false,
    "created_by": "admin",
    "updated_by": "admin"
  }
}
```

注意：顶层 `status=3` 是原有完成码；`data.status` 才是批次状态字符串。成功响应没有统一的 `ok:true`。`roles` 数组中的材料名为 `key`、`chain`、`identity`。

应用或状态查询结果中还可能包含 `backup_id`、`pending`、`services` 等字段。以下只展示需要前端关注的部分字段，不是完整响应：

```json
{
  "data": {
    "status": "installed",
    "pending": ["tems"],
    "services": {"tems": "failed"}
  }
}
```

```json
{
  "data": {
    "status": "applied",
    "pending": [],
    "services": {"tems": "success", "nginx": "success"}
  }
}
```

仅返回本批次相关服务，不能要求每次都有 nginx 和 tems。应用错误响应经过全局格式化后可能没有 `data`，应另调状态接口取得这些信息。

## 5. 原有接口调整

本节列出原有入口的 `pki_mode` 放置位置。除新增参数及外部身份来源衔接外，保留既有业务流程；旧客户端不传参数仍可调用。

| 方法 | 路径 | 参数格式（增加的参数均为可选 `pki_mode=general`） |
| --- | --- | --- |
| GET | `/api/cert/mode` | query：pki_mode |
| POST | `/api/cert/csr` | JSON：pki_mode、role、name、可选 ip/dns |
| GET | `/api/cert/csr/export` | query：pki_mode、role；返回 CSR 文件 |
| POST | `/api/cert/identity/import` | form-data：pki_mode、role、file、可选 chain |
| GET | `/api/cert/ca` | query：pki_mode |
| POST | `/api/cert/ca/import` | form-data：pki_mode、file、fingerprint（多根重复字段） |
| POST | `/api/cert/https/csr` | 兼容原无 body；新调用可传 JSON：pki_mode |
| GET | `/api/cert/https/csr/export` | query：pki_mode；返回 CSR 文件 |
| POST | `/api/cert/https/identity/import` | form-data：pki_mode、file、可选 chain |
| POST | `/api/cert/https/apply` | 兼容原无 body；新调用可传 JSON：pki_mode |
| GET | `/api/cert/https/status` | query：pki_mode |
| GET | `/api/cert/identity` | query：pki_mode、role |
| GET | `/api/cert/check` | query：pki_mode、role |
| GET | `/api/cert/export` | query：pki_mode、role；返回证书链文件 |
| GET | `/api/cert/crls` | query：pki_mode |
| POST | `/api/cert/crls/import` | form-data：pki_mode、file、可选 chain |
| POST | `/api/security/certificates/import` | 通用 Modbus 身份导入别名，同 identity/import 参数 |
| POST | `/api/security/certificates/verify` | JSON：pki_mode、role；保留原验证响应格式 |

本表旧 Modbus 身份接口的 role 为 `master` / `slave`，HTTPS 使用专用路径。GET 参数示例：

```text
GET /api/cert/identity?pki_mode=general&role=master
```

通用 CSR 请求示例：

```json
{
  "pki_mode": "general",
  "role": "slave",
  "name": "device-01",
  "ip": ["192.168.2.136"],
  "dns": ["device-01.example.local"]
}
```

role、name 必填；ip/dns 可选，接受字符串或字符串数组，每类最多 32 项。HTTPS CSR 继续从设备配置取得身份信息，例如：

```json
{"pki_mode": "general"}
```

原 `/api/cert/mode` 返回的 `mode: external_ca` 是既有 CA 配置语义，不是本次 general/trina 的整机模式，前端不要据此自动切换流程。

旧通用证书导入仍要求本地 CSR 等原校验条件，直接修改 pki_mode 无法导入外部私钥身份。CSR/证书导出需按文件（如 responseType=blob）处理，不能按普通 JSON 成功响应解析。

## 6. 外部身份的后续维护

定制应用成功安装后按角色记录外部身份来源。HTTPS 自动维护行为调整为：

- 临近过期：报告 `renewal_required`、`external_issuance_required`，不自动生成 CSR。
- 证书无效或证书/私钥缺失：报告异常并返回失败，不生成新密钥或替代证书。
- 身份有效：保持现有部署与通信行为。

当前 Modbus 没有自动生成 CSR 的定时维护逻辑。手动调用旧 CSR 接口不会清除外部来源；只有旧通用身份导入成功后，才清除对应角色的外部来源，恢复通用维护流程。前端若提供这一转换操作，应明确告知用户后续维护方式会改变。

## 7. 错误处理与联调定位

完整应用的全局错误格式化会处理 HTTP 400 及以上响应，典型示例：

```json
{
  "ok": false,
  "code": "CUSTOM_PKI_APPLY_FAILED",
  "trace_id": "<请求跟踪编号>",
  "message": "Service temporarily unavailable"
}
```

4xx 的 message 通常为错误码，5xx 为通用消息；不要依赖 message 包含脚本具体原因，也不要假设错误体包含 pending/services。定位时记录请求路径、HTTP 状态、code、trace_id，可关联响应头 `X-Trace-Id` 和后端日志。

| HTTP | 典型 code | 前端处理 |
| --- | --- | --- |
| 400 | `PKI_INVALID_REQUEST` | 检查模式、角色、文件、请求格式 |
| 401 | `SESSION_INVALID` | 按现有登录失效流程处理 |
| 403 | `FORBIDDEN` | 检查管理员权限、CSRF；具体拦截原因查认证日志 |
| 409 | `PKI_BATCH_CONFLICT` | 检查批次是否已安装、材料是否被其他入口变更或存在待恢复状态 |
| 422 | `PKI_VALIDATION_FAILED` | 检查材料、密钥匹配、信任链、指纹和批次编号；暂存批次可修正后重试 |
| 503 | `CUSTOM_PKI_APPLY_FAILED` | 查询批次状态，服务问题处理后用原批次重试应用 |
| 503 | `PKI_UNAVAILABLE` | 检查设备脚本、存储、超时及恢复状态，不直接假定已安装 |

不存在或无效的批次不保证返回 404，可能返回 422。认证限流、账号锁定等仍沿用原有处理。

## 8. 联调验收清单与当前验证范围

- [ ] 旧客户端不传 pki_mode 的现有请求仍正常；显式 general 正常，旧接口传 trina 被拒绝。
- [ ] 新接口漏传模式、传 general/非法枚举被拒绝；错误可显示 trace_id。
- [ ] 三种角色分别完成“私钥 → 根 → 中间链/clear → 叶证书 → 应用 → 查询”，全程同一批次。
- [ ] 上传后生效证书不变；应用成功后相应服务实际使用新证书。
- [ ] 根完整指纹、多根重复字段、错误指纹、私钥不匹配、角色 EKU/SAN 错误有明确失败反馈。
- [ ] 仅换证书时复用原材料；更换共享根时不破坏其他已有身份。
- [ ] 服务应用失败或 HTTPS 连接中断后，可查批次状态并用原批次重试，不重复上传已安装批次。
- [ ] 已安装批次禁止改材料；创建新批次可继续替换。
- [ ] 外部 HTTPS 身份临近过期或异常时只报告，不自动发 CSR；显式回到通用导入后恢复通用行为。
- [ ] 下载按文件处理，私钥内容不出现在日志、埋点或浏览器持久存储。
