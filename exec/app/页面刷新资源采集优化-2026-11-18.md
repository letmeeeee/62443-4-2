# 页面刷新资源采集优化

前端刷新同时调用 cpu-usage、memory-usage、disk-usage、network-rules、maintenance、login-notice、peer-status 和 status。请求耗时包含采样等待、认证和数据库访问，不能直接作为 CPU 消耗量。

## 本次调整

- `/api/system/cpu-usage`、`/api/system/disk-usage` 和 `/api/security/status` 共用同一进程内一秒有效的 CPU 样本。保留原来的 0.2 秒采样窗口与返回字段；并发请求只执行一次采样，失败不缓存。
- `/api/security/network-rules` 在每个 Flask 应用进程内复用两秒有效的公开采集结果。并发请求合并采集，减少重复启动两次 `ip` 和一次 `firewall-cmd --list-all-zones`。接口与网卡采集失败不缓存；规则、网卡和路由变化最多两秒后可见。
- `/api/security/status` 中证书自检仍使用此前的 PKI 查询缓存。
- 内存、磁盘容量、维护状态、登录提示、对端状态、审计状态和会话容量仍按原逻辑读取。认证、权限、CSRF 每次请求照常执行。

接口路径、请求参数和响应结构不变，前端无需配合调整。

## 边界与部署

这是短时间重复查询与并发刷新优化。缓存过期后的首次查询仍执行实际命令与证书校验，不能据此保证设备首次刷新没有 CPU 峰值。多个服务进程分别采集，不共享缓存。尚未测量目标 ARM 设备的 CPU 峰值，耗时与占用需部署后验证。

部署本次修改需同步 `routes/route_security.py`、`utils/system_usage.py` 和新增的 `utils/public_read_cache.py`，再重启 Flask 服务。此前 PKI 查询缓存相关文件也需要保持完整。无需更新证书、私钥或重编译 Modbus 程序。

测试覆盖并发合并、过期重新采集、返回值隔离、不同应用隔离、失败重试，以及网络规则接口重复调用不再重复启动命令。测试使用本地临时数据库和命令替身，不操作设备防火墙。
