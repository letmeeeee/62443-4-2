# 安全审计与业务操作日志接口

安全审计与业务日志分别读取 `security_audit`、`operation_log`，不再联合查询。现有数据库表和历史记录不迁移、不改写。

| 用途 | 接口 | 权限 |
|---|---|---|
| 安全审计查询 | GET `/api/history/getSecurityAudit` | 等级4 |
| 安全审计CSV导出 | GET `/api/history/export` | 等级4 |
| 独立审计状态 | GET `/api/history/status` | 等级4 |
| 业务操作日志查询 | GET `/api/history/getOperationlog` | 等级3或4 |

两个查询都返回 `{total,pageNum,pageSize,operationLogList}`。`getOperationlog` 现只返回业务日志；前端安全审计页面必须改用 `getSecurityAudit`。`GET /api/security/roles` 的能力矩阵中，audit:read/audit:export 为 `[4]`，business-log:read/business-log:export 为 `[3,4]`。已有安全汇总仍允许等级3或4查询资源、容量及故障元数据，不返回审计记录正文。

## 查询条件

- 两类查询均要求 beginDt/endDt，为设备本地无时区时间，开始不晚于结束；pageNum 默认1，pageSize 默认20、范围1～500。
- 安全审计：operationType 为事件类型字符串，例如 `account.disable`；operationTarget 为对象文本精确匹配，例如 `alice` 或备份编号。不再将安全审计目标解释为设备编号。
- 业务日志：operationType 沿用数字业务分类，operationTarget 沿用原设备编号映射。业务查询返回该表原有字段，不补造安全审计的来源、会话或变更摘要。
- operator 为操作人精确匹配；result 为0失败、1成功。
- 审计导出只读安全审计表，最多10000条，写入导出审计失败时返回503。CSV公式安全处理及X-Audit-Id保持。
- 安全审计支持数字类型筛选旧记录，但数字选择器匹配原枚举值，不会自动匹配全部新事件类型。

## 新记录的类型、对象与备注

| 类型示例 | 对象示例 |
|---|---|
| authentication.login | 成功认证的账号；失败时为待核验账号 |
| account.create / account.update / account.delete | 经后端确认的目标账号 |
| account.enable / account.disable / account.role.update | 经后端确认的目标账号 |
| account.password.change / account.password.reset | 实际改密或重置的账号 |
| session.lock / session.unlock / session.logout / session.revoke | 当前会话或后端确认的账号与会话管理标识 |
| configuration.update / network.address.update | 设备INI或网络地址配置 |
| parameter.update | 从后端设备映射解析的设备及参数地址 |
| register.read / register.write | 后端Modbus代理寄存器及已校验地址 |
| system.ssh.update / system.reboot | SSH服务或本机设备 |
| certificate.trust.import / certificate.identity.import | CA根信任、HTTPS身份或已校验的Modbus身份角色 |
| backup.create / backup.validate / backup.download / backup.restore | 后端确认的备份编号；尚未确认的请求编号明确标为待核验 |
| audit.export | 安全审计记录 |

权限拒绝或其他处理未能确认对象时，使用“未确认的目标账号”等标记，不信任前端自报的操作人名称。未知路由使用 http.request 和未确认业务对象，不全部归为参数修改。

`remark` 保存请求方法、接口路径、HTTP状态及规范化错误码；不保存完整查询串或原始请求体，也不自动写入密码、明文令牌、私钥等。操作人来自认证上下文，认证前无法确定身份时记为 `-`。保留source_ip、会话摘要、trace_id及已有公开变更摘要。

恢复、出厂恢复和身份清除的执行前许可记录使用 `backup.restore.authorize`、`factory.reset.authorize`、`decommission.authorize`，表示许可已通过；最终请求记录单独表示实际请求处理结果。不能把授权记录当成恢复已完成。

同一业务操作仍可能在业务表和安全审计表分别产生记录，这是两种用途的独立记录。旧业务表未增加trace_id，不能保证所有历史业务记录与审计一一关联。

## 历史与部署

旧安全审计记录可能仍以接口路径作为operation_target、采用旧事件分类；查询按原始记录返回，不进行猜测性重写。现有数据库无需字段迁移。更新程序后需重启后端，前端同步新查询路径、类型显示及等级4权限。

安全审计留存仍默认180天，只清理安全审计表。存储空间80%预警、95%严重告警及写入失败锁存规则不变。容量采集使用配置路径所在文件系统，非两张日志表占用量相加。
