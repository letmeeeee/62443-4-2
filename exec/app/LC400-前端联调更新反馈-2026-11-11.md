## 一、变更接口

| 方法 | 接口 | 更新内容 |
| --- | --- | --- |
| GET | `/api/security/certificates` | 每次请求执行设备身份私钥自检，返回实际结果及原因 |
| GET | `/api/security/status` | `checks.certificates.data` 同步执行私钥自检 |
| GET | `/api/security/config-summary` | `certificates` 同步执行私钥自检；`networkRules` 同步采用新的 firewalld 结构 |
| GET | `/api/security/peer-status` | 新增 logger 活动 TLS 连接快照读取，认证成功后发布对端公开证书，断开后清理 |
| GET | `/api/security/network-rules` | 由 nftables 原始规则改为 firewalld 运行时区域配置，结构化返回显式端口、服务及规则条件 |

上述接口沿用现有登录认证和权限等级 3/4，无新增请求参数。GET 请求不需要额外提交 CSRF Token；仍须携带现有有效会话凭据。

## 二、证书私钥状态不再固定为 null

### 2.1 字段及展示

完整证书条目增加实际自检结果：

```json
{
  "role": "https",
  "privateKeyVerified": true,
  "privateKeyCheckReason": "VERIFIED"
}
```

| 字段 | 值 | 建议展示 |
| --- | --- | --- |
| `privateKeyVerified` | `true` | 私钥自检通过 |
| `privateKeyVerified` | `false` | 私钥自检失败，结合原因展示 |
| `privateKeyVerified` | `null` | 未能完成检查，或不适用；不能显示为“通过” |
| `privateKeyCheckReason` | 原因码 | 显示对应说明，保留未知原因码的兜底展示 |

三个接口的字段位置如下：

| 接口 | 证书数组位置 |
| --- | --- |
| `/api/security/certificates` | `data` |
| `/api/security/status` | `checks.certificates.data`；先检查 `checks.certificates.available` |
| `/api/security/config-summary` | `certificates` |

它们共用自检流程，每次请求重新检查，不是读取上一次证书列表查询的缓存结果。

### 2.2 原因码

| `privateKeyCheckReason` | 含义 |
| --- | --- |
| `VERIFIED` | 持钥自检通过 |
| `NOT_APPLICABLE` | 不适用，例如 CA 根证书不持有设备身份私钥 |
| `INVALID_CERTIFICATE` | 当前证书无法解析，不能执行自检 |
| `PRIVATE_KEY_NOT_FOUND` | HTTPS 私钥文件不存在 |
| `INVALID_PRIVATE_KEY_FILE` | HTTPS 私钥文件类型、大小或符号链接检查不通过 |
| `INVALID_PRIVATE_KEY_PERMISSIONS` | HTTPS 私钥所有者或访问权限不符合要求 |
| `PRIVATE_KEY_MISMATCH` | HTTPS 私钥与证书公钥不匹配 |
| `PRIVATE_KEY_SELF_TEST_FAILED` | 私钥解析、签名验签或 Modbus 持钥检查失败 |
| `PRIVATE_KEY_CHECK_TIMEOUT` | Modbus 检查命令超时 |
| `PRIVATE_KEY_CHECK_UNAVAILABLE` | 检查工具或文件访问等执行条件不可用 |
| `PRIVATE_KEY_ALGORITHM_UNSUPPORTED` | 当前算法不支持检查 |
| `CERTIFICATE_CHANGED_DURING_CHECK` | 采集与检查期间证书发生变化，本次结果不能确认 |

Modbus 检查命令的失败统一归为 `PRIVATE_KEY_SELF_TEST_FAILED`，前端不能仅凭这个原因进一步断言是密钥缺失、密钥不匹配或 TEE 故障。

### 2.3 展示与调用注意事项

- `master`、`slave` 复用现有 file/TEE 后端的持钥检查；HTTPS 使用现有文件私钥签名随机挑战，并用证书公钥验签。
- 查询不会生成或轮换密钥，不导出 TEE 私钥。`ca-root` 返回 `null` / `NOT_APPLICABLE`。
- `chainVerified`、`validityStatus`、`privateKeyVerified` 是不同检查维度，应分别展示。私钥通过不代表证书链或有效期通过，也不表示证书未吊销。
- `revocationStatus` 仍为 `unavailable`，尚未接入 CRL/OCSP；不能展示为“未吊销”。
- 原 `status`、`errorCount` 和安全状态中的证书告警判定没有改为私钥检查结果的汇总。前端应直接读取 `privateKeyVerified` 展示私钥异常，不要只依赖这些汇总字段。
- 每次查询会增加耗时，Modbus 检查单角色超时为 15 秒。前端应避免重叠轮询，并结合设备实测设置请求超时；不要认为整个接口最多耗时 15 秒。
- 私钥检查失败或无法执行时，通常仍返回完整列表，并在条目中体现结果；整体证书采集失败仍按原接口错误处理。

## 三、网络规则改为读取 firewalld

### 3.1 数据来源变化

`GET /api/security/network-rules` 现在执行只读查询：

```bash
ip -j address show
ip -j route show
firewall-cmd --list-all-zones
```

不再将 `nft -j list ruleset` 的完整结果直接返回

`source` 由 `kernel-iproute2-nftables` 改为 `iproute2-firewalld`。`rules` 的内部结构已改变，前端需要同步修改解析逻辑。

### 3.3 页面适配建议

| 页面区域 | 适配方式 |
| --- | --- |
| 网口表格 | 继续从顶层 `interfaces`、`routes` 提取网口、地址、掩码、网关和状态 |
| 区域选择 | 按 `rules.zones` 展示区域，标记 `active`；可优先显示 public 或活动区域，但不能把所有非活动区域都当作已作用于当前入口 |
| 显式端口表格 | 遍历所选区域的 `ports`，读取 `port` 和 `protocol`；端口是字符串，需支持范围 |
| 来源展示 | 显示区域 `interfaces`、`sources` 绑定条件；`sources:[]` 不应直接解释为全设备任意来源，因为区域还可能通过接口或默认区域选择生效 |
| 动作展示 | `ports` 表示该区域的显式放行端口，可标记“区域显式放行”，并同时提供 target、服务和复杂规则详情；不要据此宣称端口实际可访问 |
| 服务展示 | 单独展示 `services`，本次未将 ssh、https 等服务定义展开成端口 |

| 导出 | JSON 导出当前响应；CSV 可按区域、端口、协议及区域绑定信息整理；安全配置摘要继续用 `/api/security/config-summary` |

本次没有新增独立的原始 nftables 查询接口，也没有新增防火墙编辑或后端文件导出接口。

### 3.4 本次返回对应的页面数据

网口表格建议默认展示 `link_type == "ether"` 的以太网接口；lo 和 can0/can1/can2 可放在详情中。没有 IP 的接口仍可显示，地址和掩码填 `—`，不要把空数组认定为采集失败。

| 页面字段 | 读取与处理方式 | 本次 net2 展示 |
| --- | --- | --- |
| 网口 | `interfaces[].ifname` | net2 |
| IPv4 地址 | 对应接口的 `addr_info` 中 `family == "inet"` 的 `local` | 192.168.2.136 |
| 子网掩码 | 将上述地址的 `prefixlen` 转为 IPv4 掩码 | 255.255.255.0（/24） |
| IPv6 地址 | `family == "inet6"` 的 `local` 和 `prefixlen`，可放详情 | fe80::b7c3:1bb7:df84:9daa/64 |
| 网关 | 在 `routes` 中查找同一 `dev` 的默认路由及其 `gateway`，不能用 prefsrc 代替 | —（本次未返回默认路由或网关） |
| 状态 | 结合 `operstate` 和 `flags` 展示 | 已连接（UP、LOWER_UP） |

net1、net3、net4 的 `operstate` 为 DOWN，`addr_info` 为空，可显示“未连接/无 IP”。区分链路状态与管理启用状态，不要仅凭 flags 中存在 UP 就显示已连接。

| public / net2 | 同上 | 502 | TCP | 区域显式放行 |
| public / net2 | 同上 | 9000 | TCP | 区域显式放行 |

### 3.5 可用性与查询范围

| 返回情况 | 含义与展示 |
| --- | --- |
| `rulesAvailable:true` 且某区域 `ports:[]` | 区域已采集成功，但没有显式端口配置；仍可能有服务、富规则或其他允许条件 |
| `rulesAvailable:false`、`rules:null`、`FIREWALLD_QUERY_FAILED` | 命令不可用、服务未运行、权限不足或查询超时等，展示“防火墙规则不可用” |
| `rulesAvailable:false`、`rules:null`、`FIREWALLD_RESPONSE_INVALID` | 命令输出无法解析，展示“防火墙规则解析失败” |

以上原因码位于 `rulesUnavailableReason`。即使顶层 `ok:true`，也须检查分项可用性；查询失败不代表没有规则或防火墙已关闭。

当前返回所有区域的运行时配置，包括非活动区域，不是永久配置。`ports` 只包含显式配置，不包含服务隐含端口；结果也不覆盖独立 firewalld policy 对象、direct 规则或其他工具设置的完整内核规则，不能当成整机有效防火墙判定。是否实际可访问还涉及区域选择、其他规则和服务监听状态。

`/api/security/config-summary` 的 `networkRules` 使用完全相同的新结构，配置摘要展示和导出也须同步适配。

## 五、区域字段解析失败的补充处理及复测结果

后续设备日志出现 `Invalid firewalld zone field`，表示错误已发生在区域内部字段或续行，而非区域标题。此前提供的 `LC_ALL=C` 完整样本仍可通过回归；仅凭当前错误日志尚不能确定实际失败行。

本次将接口内部 firewalld 查询固定为 `LC_ALL=C`，防止应用进程语言环境导致字段本地化；富规则解析改为识别 `rule ` 内容，不再依赖固定空格缩进，兼容制表符。发生解析异常时，DPrint 增加行号、区域、前一字段和截断的失败行内容；HTTP 返回结构不变，也不将无法解析的规则静默丢弃。

相关回归累计 103 项通过，含语言环境传递、空格/制表符富规则和失败行诊断。2026-11-11，设备端复测反馈“解析正常”，本次防火墙规则解析问题已验证修复。前端可继续使用 `rules.zones[].ports` 展示显式端口，并结合 `services`、`richRules` 和区域绑定信息展示规则；页面和导出验收仍需单独确认。

## 登录提示中英文文案补充

`GET/POST /permission/login-notice` 增加 `text_en`，与原中文字段 `text` 共同保存在同一条应用安全设置中，无需数据库字段迁移。GET仍可在登录前调用，POST仅等级4并要求有效会话及CSRF头。

POST示例：

```json
{
  "enabled": true,
  "text": "仅限授权人员使用。所有操作可能被记录和审计。",
  "text_en": "Authorized users only. All operations may be recorded and audited."
}
```

保存表单建议同时提交最近一次GET取得的version，字段名为expectedVersion。冲突返回409 NOTICE_CONFLICT，中英文、启用状态任何一项变化都会更新同一个版本号；内容不变则不递增。

前端用普通文本渲染：中文界面取text，英文界面优先取非空text_en，否则回退text；enabled=false时隐藏提示。text为1～4000字符，text_en可省略或为空，最长4000字符。后端不自动翻译，配置人员应同时提供对应英文。

兼容规则：旧自定义记录没有英文时返回text_en=""；旧客户端不传text_en时，若中文未改则保留英文，中文修改则清空旧英文。这样不会把旧翻译误用于新中文。仅修改启用状态不会清空英文。


## 六、活动 Modbus TLS 对端证书查询

`GET /api/security/peer-status` 已从固定空结果改为读取 logger 的活动 TLS 对端快照，角色权限仍为 3/4。
认证成功后，每条连接的公开叶证书及连接信息保存在 `/run/lc400/modbus-peers/`，不保存私钥或会话密钥。独立线程处理文件，通信线程不执行 PEM/JSON 文件写入。连接关闭或终止性收发错误后移除记录，并在下一次后台发布时清理相应 PEM，通常约 1 秒内完成。相同证书的多个连接使用独立文件，一个连接断开不影响其他连接。正常退出和下次启动会清理状态；异常退出时，Flask 通过进程身份和心跳拒绝旧状态，文件不能保证在进程被强制终止的瞬间删除。

成功结构示例（不是当前设备实测数据）：

```json
{
    "data": [
        {
            "authenticationStatus": "verified",
            "connectedAt": "2026-11-11T03:11:28Z",
            "connectionId": "2075142-1794366688-171288465-1",
            "connectionStatus": "connected",
            "localRole": "slave",
            "peerCertificate": {
                "issuer": "CN=LC400 Enterprise Issuing CA",
                "notAfter": "2027-11-06T01:26:29+00:00",
                "notBefore": "2026-11-06T01:21:29+00:00",
                "sha256": "e2d577de4cf9dddee9532b47945e4eee010c8288ba33983c3178cbfd0f35ba97",
                "subject": "CN=PC-debug-001-master"
            },
            "peerIp": "192.168.2.254",
            "peerPort": 64016,
            "transport": "tls"
        }
    ],
    "liveAuthenticationTelemetryAvailable": true,
    "ok": true,
    "sampledAt": "2026-11-11T03:12:45Z",
    "scope": "modbus-tls-active-connections"
}
```

前端处理：

| 状态 | 展示建议 |
| --- | --- |
| liveAuthenticationTelemetryAvailable=true 且 data 非空 | 展示本机角色、对端 IP/端口、连接建立时间、认证结果及 peerCertificate 信息 |
| liveAuthenticationTelemetryAvailable=true 且 data=[] | 暂无活动已认证 TLS 连接；不要扩大解释为全部 Modbus 设备离线 |
| liveAuthenticationTelemetryAvailable=false | 显示遥测不可用及 reason，不显示“没有连接”或“认证失败” |

表中的 available 对应 `liveAuthenticationTelemetryAvailable`。`reason` 可能为 `PEER_STATE_UNAVAILABLE`、`PEER_STATE_STALE`、`PEER_PRODUCER_UNAVAILABLE`、`TLS_DISABLED`、`PEER_COLLECTION_INCOMPLETE`、`PEER_STATE_INVALID`、`PEER_CERTIFICATE_READER_UNAVAILABLE`。状态心跳超过 5 秒或生产进程失效时不返回旧连接；更新/清理竞争可能短暂返回不可用，下次轮询重试即可。

`localRole` 是本机角色，slave 模式看到的 peerPort 可能是对端临时源端口。只覆盖统一传输层登记的 Modbus TLS 连接，不包含明文/RTU；同一设备可有多个连接，不可直接用数组长度当设备数量。接口不新增 lastSeenAt/lastRxAt 字段，也不提供证书文件路径或下载入口。握手成功认证不代表持续吊销检查。

本地验证：Python 相关回归 **124 项通过**；原生 C 以 `-Wall -Wextra -Werror` 编译并完成真实本机双向 TLS Modbus 收发、C 快照到 Flask 读取、逐连接断开删除、正常退出清理、强制终止后的失效与重启清理，以及目录不可写仍正常通信。ARM64/TEE 设备部署和前端页面展示仍待实机联调。


## 七、PCS 固件版本位域格式更新

`GET /api/device/pcs/versions?pcs=1,2,3,4` 保留当前 FC4 地址 `2600 + (n-1)*300 + 4` 和连续 8 字布局，每字依次对应 controller、sdsp、sfpga、cdsp、j1dsp、j1fpga、j2dsp、j2fpga。返回层级、组件名称和角色 3/4 权限不变，组件 version 改按位域解码，不再将整字直接拼接成版本数字。

| 位域 | 含义 | 格式 |
| --- | --- | --- |
| bit0～9 | 主版本，0～1023 | 按百分位格式化，100 → 1.00，205 → 2.05，1023 → 10.23 |
| bit10～12 | 子版本，0～7 | 十进制数字 |
| bit13～15 | 功能定义，0～7 | 0 → M，1 → P，2 → V；3～7 → RESERVED_n |

例如组件返回 `{"name":"controller","version":"V1.00-0-M"}`。M 表示主版本功能开发，P 表示并机功能开发，V 表示离网功能开发。保留功能码示例为 `V1.00-0-RESERVED_3`，不得映射为 M/P/V。寄存器全零按有效位域值返回 `V0.00-0-M`，不新增“零值即缺失”的判定；寄存器读取缺失或短读仍按原有错误处理，不用零填补。

前端按 version 字符串展示，不再假设为旧的点分多字版本。位域常量和组件顺序统一定义在 constent/common.py。系统版本接口 `/api/system/versions` 的 `data.pcs[].version` 也已复用同一位域解析，非零值返回相同格式，原有零值返回 null 的行为保留；protocolVersion、softwareVersion、patchNumber 不变。
