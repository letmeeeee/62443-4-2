# LC400 前端需求反馈：按配置展示 PKI 管理流程

日期：2026-11-17

本文是页面交互需求，不表示相关配置接口已经实现。现有证书接口路径和请求参数继续沿用。

## 1. 需求背景与目标

当前网页同时提供通用、定制两套 PKI 操作，容易混用 CSR、外部私钥导入和应用入口。
调整为根据设备配置，仅显示一套身份配置流程；证书和服务状态继续完整展示。

本阶段采用设备级流程选择，统一控制 Modbus master、slave、HTTPS 的页面操作。
不新增按角色选择模式的交互，不改变 TEE 管理页面。

## 2. 模式定义

| 显示名称 | 枚举值 | 说明 |
| --- | --- | --- |
| 通用 | `general` | 设备生成 CSR，外部 CA 签发后导入证书 |
| 定制 | `trina` | 外部提供设备私钥和已签发证书，上传后按批次应用 |

“页面选择的流程”与“已有证书的身份来源”是不同概念：例如配置为定制时，设备仍可能
保留通过通用流程导入的证书，应照常展示其状态，不能隐藏或自动转换。

## 3. 配置能力及前后端边界

### 当前已实现

- 旧操作接口接收 `pki_mode=general`，省略时兼容原调用。
- 定制操作接口要求 `pki_mode=trina`。
- 两套接口分别执行各自校验，不会因页面隐藏而自动禁止另一套入口。

### 本需求仍需后端配套

需要增加设备级、可持久化的“PKI 管理流程”配置，并提供读取能力；管理设置中允许
管理员修改，刷新页面或设备重启后仍保持所选值。具体存储字段和读写接口尚未确定，
前端不能据此文档调用假定的新路径。配置值仅使用上述 `general` / `trina` 枚举。

不能使用以下信息代替此配置：

- `/api/cert/mode` 中的 `mode=external_ca`：这是现有 CA 配置语义。
- 某次请求的 `pki_mode`：这是调用参数，不是持久化设备模式。
- HTTPS 当前证书的 `pki_mode`：它描述该身份来源，不代表三个角色的页面模式。
- 浏览器 localStorage 中的选择：不能作为设备配置的唯一依据。

配置接入前可开发页面条件展示逻辑，正式启用以配置读取能力就绪为前提。不要修改
现有证书操作接口的路径、参数格式或认证方式，也不要求新增清理或重置调用。

## 4. 页面展示规则

| 页面区域 / 操作 | 通用 general | 定制 trina |
| --- | --- | --- |
| 当前流程标识、流程说明 | 显示通用说明 | 显示定制说明 |
| master / slave / HTTPS 身份选择 | 显示 | 显示 |
| 生成、导出 CSR | 显示 | 隐藏 |
| 外部设备私钥上传 | 隐藏 | 显示 |
| 已签发叶证书导入 | 通用导入组件 | 定制批次导入组件 |
| CA 根导入 | 通用根导入 | 定制批次根导入 |
| 中间链输入 | 沿用通用导入的可选 chain 字段 | 独立上传或 clear=true |
| 应用按钮 | 沿用通用应用流程 | 明确标识“校验并应用当前批次” |
| 批次材料及状态 | 不展示定制操作表单 | 显示 staged / installed / applied |
| 证书信息、有效期、指纹、检查与导出 | 始终保留对应能力 | 始终保留对应能力 |
| CRL、待应用服务、应用失败信息 | 始终可见 | 始终可见 |

隐藏另一套身份操作表单和按钮，不隐藏已有证书、异常身份或未完成服务状态。
页面上的私钥上传是设备身份私钥，不是 CA 私钥；提示仅支持未加密 PEM 普通
RSA-2048/3072，拒绝 RSA-PSS 私钥，三个角色使用不同私钥。

## 5. 接口调用注意事项

### 通用身份操作

继续调用原 CSR、身份导入、根导入及应用接口，按原请求类型携带 `pki_mode=general`。
通用身份导入仍执行原 CSR 校验，不能靠改变参数绕过。

### 定制身份操作

继续调用 `/api/cert/custom/` 下的 key/ca/chain/identity 导入及 apply/status。
首次上传取得 batch_id，后续上传、应用、查询沿用同一编号。多个批次可以并存，
页面切换不触发历史清理。上传成功只表示暂存，不表示证书已生效。

CA 根共享，只需在当前批次上传一次，不需要按三个角色重复上传。
没有中间 CA 时使用 `clear=true`，不传 file；不要用空文件代替。
应用必须调用 custom/apply，不能误用旧 HTTPS apply 安装定制暂存材料。

### 公共管理与只读查询

按页面配置显示一套流程，不等于全部请求都携带同一 pki_mode。现有 CRL 上传、
证书查询、检查和导出仍使用各自已有接口及其允许的参数（旧接口为 general），
定制页面也可能需要调用这些公共入口。不要全局拦截并重写所有请求的 pki_mode。

共享根迁移时，原 CRL 上传入口可将匹配暂存根的 CRL 自动关联到批次。前端仍使用
原格式，无需增加新的 CRL 接口或字段。

管理员认证、POST CSRF、文件下载响应处理保持原规则。完整字段及响应约定参考
[PKI 联调反馈](LC400-前后端联调反馈-PKI模式变更-2026-11-16.md) 和
[定制 PKI 说明](CUSTOM_PKI.md)。

## 6. 模式切换和异常交互

- 常规证书页面显示当前配置，不放置可随意切换操作流程的临时标签；切换通过管理
  设置完成，以后端保存成功的配置为准。
- 切换只改变后续页面可操作流程，不删除证书、私钥、根、CRL或历史批次，不生成
  CSR，不触发服务重启，不自动改变已有身份来源。
- 用户有未提交表单或暂存批次时，切换前提示：“切换仅改变配置流程，未应用材料
  不会自动生效或删除。”允许用户取消切换，不自动丢弃服务器批次。
- 上传或 apply 尚在执行时，当前页面暂停切换，避免提交落入错误流程。切换完成后
  隐藏原表单并清除其可提交状态；暂存编号可以保留用于恢复，不保存私钥内容。
- 既有身份来源与当前流程不一致时，仅显示来源说明，不自动导入、生成 CSR 或修正。
- 定制身份异常或临近过期，提示外部重新签发并导入，不自动调用旧 CSR 接口。
- 配置读取失败、值非法或尚未配置时，保留只读状态信息，禁用身份写操作并提供重试
  或前往设置入口，不静默猜测通用/定制模式。已有配置可短暂展示缓存值，但不能据此
  在配置未确认时提交写请求。
- apply 超时或 HTTPS 连接中断，先查询原批次状态；不要自动创建新批次或重新上传。

## 7. 验收清单

- [ ] general 仅展示通用身份操作；trina 仅展示定制身份操作，无两套应用按钮混杂。
- [ ] 刷新页面、重新登录、设备重启后，根据同一设备配置展示一致流程。
- [ ] 三个角色的已有证书、异常状态和身份来源均保持可见。
- [ ] 切换流程不会自动改动证书、密钥、CSR、根、CRL、批次或服务。
- [ ] 配置读取失败、非法或未配置时，不产生猜测模式的写请求。
- [ ] 定制表单使用原 batch_id 规则，公共查询/CRL 请求不被强制改成 trina。
- [ ] 隐藏流程不会继续因监听器、定时器或旧表单提交触发写操作。
- [ ] 私钥内容不进入日志、埋点或浏览器持久存储。
- [ ] 现有非 PKI 模块和 TEE 管理页面不受影响。

本需求不包含禁止另一套后端接口的策略，也不包含新增 PKI 出厂重置接口。
